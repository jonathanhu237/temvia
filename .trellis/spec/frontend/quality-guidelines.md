# Frontend Quality Guidelines

## Scope

These rules cover the owned React starter in template/admin/ and its generated admin/ output. The root package.json belongs to the generator; it is not a frontend workspace.

## Commands and boundaries

- Run pnpm install inside admin/; its packageManager field pins the package manager.
- pnpm check runs tsc -b. pnpm build runs the TypeScript check and Vite build. pnpm dev runs Vite.
- Browser and Vite/Node TypeScript settings are separate configs inside admin/.
- Keep React dependencies, configuration, and the application's lockfile within admin/. Do not introduce a root workspace or shared frontend package without a later requirement.
- The initial page is static. It does not require an API fetch, router, UI kit, data store, database, or credentials.
- Vite binds to 127.0.0.1 and prefers port 5173. Omit strictPort to preserve Vite's default fallback to an available port; the starter has no requirement for a fixed admin port.
- CLI next steps and the generated README must direct users to the URL printed by Vite, not promise that 5173 is always the actual port. Port forwards must target the selected port.

## Installation and template artifacts

The initial seed contains no lockfile. The first install resolves transitive dependencies and generates the application's own pnpm-lock.yaml; keep that generated lockfile in the consuming project.

pnpm 11 can also create an admin-local pnpm-workspace.yaml containing minimumReleaseAgeExclude for an explicitly pinned recent dependency. This is local package-manager configuration, not a generated root workspace. Do not disable its safety checks to suppress the file.

When developing the template, exclude its local lockfile and pnpm-workspace.yaml from Git, generation, and npm packing. Also exclude node_modules/, dist/, build-info files, and secrets. Test pollution explicitly; a pristine source tree alone will not reveal these mistakes.

## Verification

- Perform application installation/typecheck/build on Centaurus after one-way rsync, using output generated by the actual npm tarball.
- Inspect the page in a browser through a local port forward. Confirm the heading renders and console errors are absent.
- For dev-listener changes, verify an occupied preferred port leads to a successful listener on another available port. Run the generated project's pnpm dev without strictPort overrides and check its printed URL through a local forward; do not add tests that only restate the configuration.
- Do not add a UI test framework merely to assert the initial static text.
- No separate JavaScript linter is configured; do not report TypeScript checks as lint.
- Preserve the committed repository-level English/Chinese READMEs during this initialization task.
