# 后台操作反馈统一

Status: resolved
Labels: ready-for-agent

## Problem Statement

管理员保存邮件配置后没有明确的成功提醒，角色、邀请等操作也缺少一致反馈。请求失败时，有些页面显示错误横幅，有些同时显示 Sonner，反馈重复且分散。用户希望明确区分表单校验与请求错误，并用统一、简洁的提示了解操作结果。

## Solution

统一检查后台操作：主动提交的操作成功及请求错误使用 Sonner；本地表单校验错误留在对应字段旁。Sonner 只显示信息，不包含业务操作按钮。移除专门的错误重试和冲突恢复按钮，加载失败或版本冲突时提示用户手动刷新页面。失败当下保留输入；手动刷新后读取最新数据，不恢复发生冲突的旧草稿。

## User Stories

1. 作为管理员，我希望保存邮件配置后收到成功提示，以便确认设置已保存。
2. 作为管理员，我希望测试邮件提交后收到准确反馈，以便区分提交发送与最终送达。
3. 作为管理员，我希望创建角色成功后收到提示，以便确认角色已建立。
4. 作为管理员，我希望编辑角色成功后收到提示，以便确认修改已保存。
5. 作为管理员，我希望删除角色成功后收到提示，以便确认操作完成。
6. 作为管理员，我希望保存用户角色分配后收到提示，以便确认分配已更新。
7. 作为管理员，我希望创建邀请后收到提示，以便确认邀请已创建。
8. 作为管理员，我希望重发或续期邀请后收到准确提示，以便确认请求已处理。
9. 作为管理员，我希望撤销邀请后收到提示，以便确认邀请已撤销。
10. 作为用户，我希望退出登录后收到成功反馈，以便确认会话退出已完成。
11. 作为管理员，我希望请求失败统一通过 Sonner 告知，以便不必寻找不同位置的错误横幅。
12. 作为管理员，我希望本地输入校验错误显示在字段旁，以便定位并修正输入。
13. 作为管理员，我希望服务端拒绝字段值时获得可理解的错误说明，以便知道提交未成功。
14. 作为管理员，我希望普通提交失败时保留输入，以便使用原提交按钮再次尝试。
15. 作为管理员，我希望版本冲突时获知需要刷新及可能丢失未保存修改，以便自行决定何时刷新。
16. 作为管理员，我希望刷新后获取最新版本，以便摆脱旧草稿造成的连续冲突。
17. 作为用户，我希望列表或设置读取失败时获知需要手动刷新，以便恢复使用。
18. 作为用户，我希望访问被拒绝时收到准确原因，以便不会误以为刷新即可获得权限。
19. 作为用户，我希望 Sonner 不含操作按钮，以便提示保持简洁。
20. 作为用户，我希望同一次操作不会重复弹出相同结果，以便避免干扰。
21. 作为用户，我希望关闭弹窗或页面跳转后仍能看到操作结果，以便不会错过成功反馈。
22. 作为用户，我希望普通读取成功不弹提示，以便正常浏览时保持安静。
23. 作为用户，我希望中英文及不同外观下反馈均清晰可读，以便沿用个人界面偏好。
24. 作为管理员，我希望保存成功的提示不暗示邮件服务器可达，以便正确理解配置与投递的区别。

## Implementation Decisions

- 范围涵盖系统设置读取和保存、测试邮件、角色列表和详情及增改删、用户列表和角色分配、邀请列表及创建/重发/续期/撤销、首页运行提醒读取、后台会话检查及退出登录、后台访问拒绝。
- 检查公共认证页面与后台共享的反馈设施，防止共享组件修改造成回归；本轮不重设计初始化、登录、邀请接受或密码恢复的完整公开流程。
- 修改现有页面、表单、查询/提交反馈和中英文文案，复用当前 Sonner 及错误翻译设施，不引入另一套通知系统。
- 操作成功以 API 确认成功为准。提交中沿用现有禁用和处理中状态，防止重复提交；不提前显示成功，不新增自动写请求重试。
- 本地校验失败不发送请求，只显示字段提示。服务端返回的校验错误属于请求错误，使用 Sonner；将可用字段错误翻译为有意义的说明，不依赖已被移除的错误横幅解释原因。
- 网络失败、异常响应、服务端业务拒绝、权限不足和版本冲突使用准确的本地化提示，不向用户展示原始异常或敏感配置。
- Sonner 不含重试、重新加载、撤销等操作按钮。删除专门用于错误恢复的页面按钮；普通提交按钮及业务本身的确认/取消按钮保持其原有职责。
- 读取失败提示手动刷新，不把失败当成成功的空列表。页面保持安全的基础布局，不显示未授权数据，也不因移除错误组件触发重复获取或无限重定向。
- 版本冲突提示内容包括记录已被其他人修改、请刷新页面及刷新将丢失未保存修改。收到冲突时保留输入，不自动刷新、重试、覆盖草稿或静默替换版本。
- 浏览器完整刷新后重新读取最新数据；现有 Zustand 草稿为内存状态，保持完整刷新清除旧草稿的能力，不新增跨刷新持久化。普通页面切换的既有草稿行为不在本轮重设计。
- 普通提交失败恢复可提交状态，用户可继续使用原提交按钮。会话失效等安全边界沿用既有鉴权和草稿清理规则，不为保留输入绕过身份隔离。
- 退出登录失败不声称已退出，不提前删除有效会话状态；成功后提示可跨跳转显示。权限不足不提示刷新即可获得权限。
- 同一请求失败只产生一次提示，不由页面和全局查询处理器各弹一次。重渲染、同一查询的多个订阅者不重复弹提示。正常导航取消请求不制造失败提醒。
- 成功提示简短且与操作匹配。邮件设置保存成功只说明配置已保存；测试邮件、邀请邮件提交不承诺最终送达。普通数据读取成功不显示 Sonner。
- 首页“邮件未配置”属于 Operational warning，是系统当前状态，不是请求错误。保留业务运行提醒及其配置入口；读取提醒失败则遵守统一请求错误规则。
- 沿用现有全局通知容器，保证弹窗打开、关闭及导航后提示可见，并兼容键盘、屏幕阅读器、中文/英文及明暗外观。
- 不修改后端 API、数据库结构、权限模型、SMTP 配置、邮件队列或乐观锁契约。本轮统一前端反馈和恢复方式。

## Testing Decisions

- 测试可见结果与用户操作，不以内部状态字段、辅助函数或组件结构作为验收目标。
- 优先复用现有浏览器测试入口，验证真实 Sonner 可见、弹窗和退出跳转后的提示、无业务操作按钮、手动刷新恢复，以及中英文和键盘可访问性。使用现有请求拦截模拟读取失败、权限拒绝、校验错误和版本冲突，不向真实邮箱发信。
- 复用现有设置和访问管理页面组件测试覆盖各主动操作成功/失败、字段校验不发请求、失败保留输入、提交期间防重及普通失败后可再次提交。将旧错误横幅和恢复按钮断言调整为已确认的新行为。
- 在现有查询与会话测试入口覆盖提示去重和会话清理，防止将本地校验异常当成请求错误，或导航取消弹错误。
- 浏览器至少贯穿一个保存成功场景、一个读取失败后刷新恢复场景及一个版本冲突后刷新读取最新数据的场景。验证冲突前输入留存、刷新后不恢复旧版本草稿。
- 测试“保存成功后刷新列表失败”这类不同请求的结果应分别准确表达，不能将已经成功的写入改报为保存失败。
- 复用已有前端类型检查、lint、测试及构建；共享组件有改动时验证公共认证流程不受影响。无后端行为变更，不为本轮新增后端测试层或新测试框架。
- 遵循项目 Centaurus 工作流：本地修改，单向同步时保护环境文件，再在远端验证并转发服务端口。规格阶段不启动或部署应用。
- 测试边界已按上述方案写入，并已通过异步问题向用户核对确认。

## Out of Scope

- 本次规格编写阶段不修改应用代码、不提交或部署、不发送真实邮件；后续实现以本规格定义的功能范围为准。
- 新的恢复按钮、Sonner 业务操作按钮、自动刷新、自动覆盖草稿、冲突合并界面。
- 通知历史、消息中心、审计系统、新增通知偏好。
- 用通知替代首页业务运行提醒、改动后端授权及邮件投递语义。
- 重设计公开认证流程或为普通页面读取增加成功提示。

## Further Notes

- 本规格以最终确认的“手动刷新、Sonner 无操作”决定为准，替换此前保留错误重试/冲突恢复按钮以及将操作放入 Sonner 的建议。
- 本规格替换旧邮件设置及访问管理规格中与本轮冲突的错误横幅和加载最新按钮要求；乐观锁和授权保护继续适用。
- 没有新增领域概念或满足条件的 ADR 决策；沿用现有 System settings、Email configuration、Role assignment 和 Operational warning 词汇。
