# 现有功能测试可靠性与鲁棒性保障

Status: open
Labels: ready-for-agent
Implementation: not-started
Baseline: a71eb8ce5157be5cbbbfdcfef3929b69a9a7c28e

## Problem Statement

现有单元测试和临时独立验收不能构成长期、可重复的质量保障。此前真实 PostgreSQL 和浏览器执行曾暴露 DSN 缺失导致集成测试跳过、夹具清理依赖已失效的级联关系、并发断言错误、页面状态不更新等问题。当前常规发布检查运行 Go 测试但未提供真实数据库，强制浏览器门禁主要是首次初始化/登录；个人设置和邮件任务的实际验收仍需要手工准备独立环境。

本轮用户授权补齐这部分，不增加业务功能，不承诺无限覆盖所有异常，而是建立风险驱动、可重复、不能静默跳过的关键路径保障。

## Solution / Scope

1. 先形成现有能力风险/测试矩阵：认证与会话、权限、个人设置、账号安全、邮件任务、系统设置/操作历史、生成与部署。每项标明实际测试入口、是否真实数据库/浏览器、现有缺口、本轮新增保护；区分已有证据和未覆盖风险，不用测试数量或覆盖率代替行为覆盖。
2. 把已确认的最高层测试入口固化：Playwright + Mailpit 的浏览器流程为主要验收，真实 HTTP API + PostgreSQL 补充安全/事务/并发；复用已有应用/SMTP适配测试边界控制故障。用户已经确认这些入口，本轮不创造新的测试私有实现接口、不重开产品访谈。
3. 建立显式的可重复“完整/关键集成验收”命令，自动准备真正隔离的 PostgreSQL、邮件/浏览器应用及账号数据，执行测试并可靠清理自身资源；不要求操作者手抄临时密码/建库/执行 scratch 脚本。可以复用/扩展已有实际 tarball 首次运行验收能力，但保留其原有精确产物保障。
4. 强制验收模式中，缺少依赖、数据库连接、Mailpit、浏览器或必需凭据必须明确失败；必需测试被 skip、未发现/未执行、意外空集合、超时或任何子命令失败都不能返回成功。普通轻量单元测试可以保留可选集成跳过，但必须清楚区分它与完整验收。
5. 为验收 runner 本身增加负向回归：缺依赖/坏配置/子进程失败/跳过必测项/超时，不能生成假绿；失败报告可排障而无密码、验证码、完整安全链接、密钥或邮件正文。清理失败须可见，不能吞掉主要失败。
6. 将关键验收接入不会发布软件的自动检查（如 PR/源码检查工作流），并使需要它的发布前检查依赖同一已验证入口；不得在本轮实际推送、触发发布、修改发布目标或放松现有发布校验。不要将所有易变的历史浏览器场景无差别塞入门禁，明确选择固定的关键测试集合并解释范围。
7. 补最重要且缺乏真实证据的行为回归：
   - 会话过期/撤销或角色撤权后的读写拒绝，安全变更后旧权限不可用；前端失效/切换账号不残留上一账号数据。
   - 个人设置独立保存、提交失败保持用户输入、实际头像/语言关键流程；验证码补发不恢复失效凭据。
   - 邮件临时失败/修复后重试、当前配置生效、轮次预算、重复提交、领取与删除/清理竞争、旧租约迟到不能覆盖新状态；实例/工作器中断后可恢复且不会永远卡发送中。
   - 可控制的数据库/SMTP故障、请求超时/断网和恢复反馈：不假成功、不损坏先前数据、恢复后可继续操作。只补矩阵确认缺失的高价值场景，不重复堆砌已有测试。
8. 用红→绿验证具体风险：先展示新增用例能捕获对应失败/回归，再只修复必要的实际缺陷。允许修复测试揭示的最小产品错误；不借机重构大块业务或加新产品能力。
9. 整理测试运行文档、必需依赖、各命令保障范围及结果格式。临时旧 scratch 验收脚本不是正式入口；不要删除它们或把凭据/环境耦合脚本直接复制为长期方案。

## Implementation Constraints

- 风险矩阵和实施证据独立记录于本功能目录，原规格/基线在实施及最多三轮累计复审期间固定。
- 优先复用现有 Go 测试、HTTP/PostgreSQL 夹具、Playwright/Mailpit、Vitest、实际 tarball gate、mise 和现有依赖；避免引入另一套测试平台、庞大框架或未授权外部服务。
- 时间控制和数据库夹具必须满足生产约束；清理显式覆盖当前独立持久的邮件/尝试数据，不能依赖旧级联关系或忽略清理错误。并发测试允许合法序列化，不断言调度的偶然次序；不得靠长 sleep 掩盖竞争。
- 真实验证涉及数据库或进程故障时，只操作自己新建的专用容器/工作器/数据库。不得停止远端宿主机 PostgreSQL、Docker 或其他应用。
- 验收 runner 需要固定/验证隔离根目录与 Compose 项目、随机/隔离端口及独立数据库，不受继承的 COMPOSE/PG/E2E/路由环境变量污染。环境错误必须 fail-fast。禁止 rsync --delete、未验证目标变量、泛化清理或删除非自身创建目录。
- 源码和 Git 在本地；实施代理仅做本地文件变更和轻量检查，不得 SSH/rsync/运行重型本地检查。父代理独占 Centaurus 同步及资源密集验证，暴露的 API/前端服务转发本地；远端不可用先报告。工具使用 mise 管理。
- 不要求兼容旧在用部署；仍保证全新生成项目包含完整测试/运行资源，严格打包清单、schema readiness 和初始化路径一致。
- 不为获取绿色结果禁用安全测试、改弱断言、放宽生产限制、默默忽略退出码或把 skip 算通过。不要承诺恰好一次 SMTP 投递或消除一切不确定性。
- 保持中英文后台文案规范和既有用户行为；无新业务入口/配置需求。若发现必须改变已确认产品行为的架构问题，记录具体阻塞，不擅自改需求。
- 禁止嵌套实施代理链。使用指定 Luna 完成该轮实施，父代理直接复审；无最终提交/推送权限给子代理。父代理验证通过后仅提交本任务 Conventional Commit，不推送。

## Acceptance / Testing Decisions

- 审计矩阵明确覆盖真实路径及本轮补充项，不以 DSN-less Go 成功声称 PostgreSQL已验证。
- 父代理在全新专用环境从正式入口至少完成一次全套选定验收；再次运行验证资源/夹具不依赖前次残留，记录成功、失败、跳过的实际数量。
- 必需依赖/跳过负向测试失败可证实；CI 的门禁与本地正式入口一致且不依赖个人 scratch 路径。
- 真实 DB并发与故障场景可重复运行，至少关键集合使用race detector/重复执行检查夹具稳定性；故障恢复与权限行为在外部接口观察。
- 核心浏览器测试启用且实际执行：主要包括登录/会话、个人设置和邮件任务路径；敏感场景禁止 trace/video/screenshot 泄漏，Mailpit读取仅在私有验收上下文中使用。
- 常规 Go test/vet/build、前端check/test/lint/build、根生成器/包/发布逻辑测试和准确tarball首次运行门禁保持通过。lint警告如保留须如实报告。
- 最终记录已解决风险、剩余明确盲区和独立命令结果，不声称“所有测试完善”或“没有缺陷”。

## Out of Scope

新增业务功能；组织/字典/文件中心等产品扩展；大规模性能压测或容量承诺；旧部署兼容层；更换认证/邮件基础设施；取消邮件等被否决产品概念；推送或发布；恢复/清理过去的事故资料及无关工作区。
