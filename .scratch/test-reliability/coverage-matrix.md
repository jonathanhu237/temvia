## Risk prioritisation

P0 for this change: a mandatory command must not report success when PostgreSQL,
Mailpit, Chromium, credentials, selected tests, or cleanup are absent; the reset,
personal settings, and mail-task paths must execute through public HTTP/browser
seams; and the tarball tested must remain the one that generated the isolated
project. P1: durable DB state, lease/race, retry policy, and operation-log
regressions need real PostgreSQL evidence. P2: broader historical E2E (online
users, system identity, all lifecycle permutations) remains useful but is not
added indiscriminately to the gate because it requires mutable seeded accounts
and has a larger flake surface.

## Evidence boundary

The matrix deliberately separates source-level/unit evidence, controlled adapter
fault evidence, and real PostgreSQL/Compose/Mailpit/browser evidence. A regular
`go test ./...` without `TEST_POSTGRES_DSN` is not evidence for the integration
rows. A Playwright invocation that reports skipped tests is not evidence for that
row. The implementation records the selected test names and actual pass/skip
counts; parent validation must run the heavy Compose/browser/DB command in a
fresh owned environment and report its result rather than treating this file as
execution evidence.
