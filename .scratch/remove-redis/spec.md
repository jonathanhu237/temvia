# 移除 Redis，以 PostgreSQL 承接现有临时状态

Status: ready-for-agent
Triage: ready-for-agent

## Problem Statement

Temvia 作为长期使用的后台应用模板，目前必须运行 PostgreSQL 和 Redis。Redis 实际承担登录会话、登录及密码重置限流状态、在线用户查询的数据来源，而非业务查询缓存。维护额外服务会给每个生成项目带来部署、配置、故障排查和测试成本，当前没有经过验证的需求证明这些成本必不可少。

用户希望默认基础设施更简单：彻底移除 Redis，以现有 PostgreSQL 承担这些职责，同时保持用户可观察的认证、会话、在线用户和限流行为。应用尚未上线，不需要迁移 Redis 中的会话或限流状态。

## Solution

生成的应用只依赖 PostgreSQL 保存现有服务端状态，不再需要 Redis 服务、客户端或配置。登录会话和现有限流状态迁入 PostgreSQL，在线用户从有效会话查询得到。

保留现有会话续期精度、过期规则、认证版本撤销规则、限流算法及额度。会话到期时立即在请求校验中失效，应用后台任务仅负责分批回收过期数据。正常重启保留尚未过期且未被撤销的会话；数据库临时故障不被误判为用户退出。

本轮是存储替换，不是新增防刷能力或项目重构。优雅停机保持现状，之前讨论的修复不在本轮实施。

## User Stories

1. As a 模板使用者, I want 生成项目无需运行 Redis, so that 部署和维护的服务更少。
2. As a 模板使用者, I want 项目不要求 Redis 地址、密码或内存配置, so that 初次配置没有无用步骤。
3. As a 模板维护者, I want 彻底删除 Redis 适配器及客户端依赖, so that 无需维护两套存储实现。
4. As a 用户, I want 正常登录和退出登录的 API 行为保持不变, so that 存储替换不会改变使用流程。
5. As a 用户, I want 普通业务请求继续按现有规则续期, so that 不会因减少数据库写入而提前过期。
6. As a 用户, I want 空闲超时后不能继续使用旧会话, so that 登录状态有明确的有效期。
7. As a 用户, I want 绝对有效期不因持续操作而延长, so that 会话不会无限续期。
8. As a 用户, I want 后台登录状态检查不续期, so that 页面自动轮询不会让空闲会话永不过期。
9. As a 用户, I want 正常重启后有效会话仍可使用, so that 发布或重启不必然要求重新登录。
10. As a 用户, I want 数据库临时故障时看到服务不可用而不是被清除登录凭证, so that 服务恢复后可以重试。
11. As a 用户, I want 数据库恢复后仍重新校验有效期与撤销状态, so that 保留凭证不等于绕过认证。
12. As a 用户, I want 退出与并发请求相遇时旧会话不会复活, so that 退出操作可靠。
13. As a 管理员, I want 强制退出继续终止目标用户的所有现有设备会话, so that 更换存储不削弱安全行为。
14. As a 用户, I want 密码重置后旧会话仍按现有规则失效, so that 账号恢复的安全语义不变。
15. As a 管理员, I want 在线用户仍表示至少有一个有效会话的用户, so that 在线状态不被改成最近活跃状态。
16. As a 管理员, I want 过期或已撤销会话不使用户显示在线, so that 在线用户列表准确。
17. As a 管理员, I want 查询在线用户不延长任何会话有效期, so that 监控行为不改变被监控状态。
18. As a 用户, I want 登录限流保持当前额度和恢复规则, so that 本轮不会混入新的限制策略。
19. As a 用户, I want 请求密码重置的限流与登录限流继续独立, so that 两种操作互不占用额度。
20. As a 模板维护者, I want 并发请求不能超额消耗令牌, so that 单实例并发处理仍然正确。
21. As a 用户, I want 额度耗尽与存储故障仍返回不同错误, so that 请求过多与服务不可用不会混淆。
22. As a 部署者, I want 应用自动分批回收过期状态, so that 无需数据库扩展或额外调度服务。
23. As a 用户, I want 清理延迟不延长登录有效期, so that 安全性不依赖后台任务及时执行。
24. As a 模板维护者, I want 生成器、测试和当前部署文档同步移除 Redis 要求, so that 生成项目完整可用。
25. As a 模板维护者, I want 现有邮件 outbox 和其他业务流程保持不变, so that 移除 Redis 不引入不相关改造。

## Implementation Decisions

- 以 PostgreSQL 为本轮唯一状态存储后端，彻底移除 Redis；不保留可选双后端，也不搭建通用缓存框架。
- 按当前单 API 实例部署实现。并发请求的数据库正确性是必需项，但多实例支持、分布式协调和集群验收不是交付目标。
- 优先复用现有会话、版本化会话、只读会话、限流和在线会话查询端口，由现有 PostgreSQL 适配层实现。仅允许完成替换所必需的局部改动，不重构目录、框架或整个认证接口体系。
- 通过现有数据库迁移机制新增会话与限流状态表及必要索引。不重写无关历史迁移，不迁移 Redis 临时状态，不要求重置现有用户、角色或设置数据。
- 会话记录具备用户关联、认证版本、最后活动时间、空闲到期时间及绝对到期时间。数据库保存高熵会话令牌的摘要用于查找，而非可直接用于认证的明文凭证；浏览器端会话契约保持不变。
- 保留现有 Cookie、安全属性、令牌生成规则、请求校验和错误响应契约，不改为 JWT 或进程内会话。
- 保留可配置的空闲及绝对超时，默认分别为 30 分钟和 12 小时。只有未过期会话可以续期，新空闲截止时间不得超过绝对截止时间。
- 普通请求与只读后台检查沿用现有 touch/no-touch 区分。不得通过采样、节流或宽限窗口减少活动时间记录精度。
- 续期与过期校验采用数据库原子操作，使用一致的数据库时间依据，避免先查询再无条件更新。续期不得重新插入已删除记录；到期或退出的会话不得被并发续期复活。
- 保留 PostgreSQL 中用户认证版本作为会话撤销的权威依据。强制退出和密码重置后的旧版本会话，即使记录尚未清理也不得通过后续认证。此要求不扩展为取消已经授权并执行中的请求。
- 在线用户查询基于尚未到期且认证版本有效的会话，保持现有用户去重、活动时间展示、权限检查和分页等外部行为；不再扫描 Redis。
- 正常应用或数据库重启不清空会话；到期或已撤销会话不因重启恢复有效。
- 数据库临时故障返回现有依赖不可用响应（503），不得作为确认未认证（401）处理，不清除浏览器登录凭证，不放行受保护操作。服务恢复后正常重新校验会话。
- 现有限流仅替换存储，保留全局与单邮箱令牌桶、命名空间隔离、现有默认值与环境变量：登录全局容量 10、每 6 秒补 1；登录邮箱容量 5、每分钟补 1；密码重置请求全局容量 10、每 6 秒补 1；密码重置请求邮箱容量 3、每 20 分钟补 1。
- 保留现有邮箱规范化、登录成功后重置邮箱桶的行为以及限流检查在业务流程中的位置。不改变全局桶的职责或阈值，不新增 IP、用户或其他维度。
- 使用短事务与固定锁定顺序原子检查两个桶；只有两个桶均允许时才共同扣减。补充计算及到期语义与原实现等价，首次并发创建和清理竞争均须正确处理。不要把密码计算或邮件发送放进限流事务。
- 限流状态标识不保存不必要的明文邮箱。数据库操作沿用项目现有的有界超时机制，避免锁等待无限占用连接。
- 额度不足保留现有 429 问题响应，数据库故障保留 503。本轮不新增 Retry-After 或新的前端提示契约。
- 应用启动后台定时清理，分批回收过期会话及安全可回收的限流状态。清理频率和批量大小由实现根据现有后台任务惯例选择，不引入数据库扩展、独立服务或额外配置面板。
- 清理不是有效性判定依据。清理失败、延迟或暂未执行只影响空间回收；不可提前重置尚受限制的桶。清理任务尊重现有取消信号，记录故障，不更改整个应用停机编排。
- 删除 Redis 服务定义、启动健康依赖、环境变量、配置验证、客户端包及专属适配器。同步更新生成器文件清单、打包规则、测试和当前运行文档，确保全新生成项目不再依赖 Redis。历史变更记录和无关上游说明无需为消除关键词而改写。
- 现有 PostgreSQL 邮件 outbox、任务租约与重试机制保持不变；不引入 MQ。
- Go Blueprint 仅作为局部实现参考，不作为目录布局或项目重构依据。本轮不采用其中的停机实现。

## Testing Decisions

- 以用户可观察行为为验收依据，不断言私有辅助函数调用次数、具体 SQL 文本或必须存在的内部类型。
- 首选现有 HTTP API + 真实 PostgreSQL 集成测试作为主测试边界，覆盖登录、当前用户、会话状态检查、退出登录、强制退出、密码重置及在线用户查询。复用现有 HTTP 在线用户集成测试和 PostgreSQL 集成测试组织方式，不新增测试框架。
- 复用现有应用层 fake 测试保留业务错误映射、认证版本和限流拒绝行为的回归覆盖；原 Redis 存储契约测试中有价值的场景迁入 PostgreSQL 集成测试。
- 在难以通过 HTTP 精确触发的存储并发及到期边界上，使用现有存储端口进行真实 PostgreSQL 测试。这是主边界的必要补充，不引入生产专用测试端点。
- 会话测试覆盖正常创建、读取、续期、空闲到期、绝对到期、后台轮询不续期、退出与续期竞争、过期记录未清理仍不可用、版本撤销、重建应用依赖后有效会话仍可使用。
- 依赖故障测试验证 503 与 401 的区别、不清除登录 Cookie，并检查前端现有错误处理不会把 503 当成确认退出；恢复后仍校验过期与认证版本。仅在必要时修正相关现有前端行为，不重做界面。
- 限流测试覆盖现有额度、补充、两个命名空间独立、不同邮箱共享全局额度、登录成功重置邮箱桶、两个桶共同扣减、首次并发创建、并发请求不超发、数据库故障映射以及清理不提前恢复额度。
- 清理测试验证分批执行、故障不改变认证有效性、任务取消以及清理与活动状态更新的竞争。避免依赖漫长 sleep，优先通过测试数据控制时间边界。
- 使用受控并发测试或小型负载实验检查限流热点锁等待与会话更新对现有连接池的影响，记录环境和结果；不宣称未经验证的 QPS，不通过随意放大连接池掩盖问题。
- 复用现有生成器及模板基线测试，验证输出文件完整、Go 依赖可解析、环境配置无需 Redis、Compose 服务图无 Redis 依赖；仅运行 PostgreSQL 及必要应用组件即可通过核心集成流程。
- 不以本轮测试要求新增 IP 限流、多实例协调、优雅停机修复或备份机制。

## Out of Scope

- 新增 IP 限流、可信代理调整、额外接口防刷、调整限流额度或全局策略。
- 修复或重构优雅停机，新增统一停机预算或 SHUTDOWN_TIMEOUT；此前讨论的默认 30 秒方案暂停实施。
- Redis 会话或限流数据迁移、双写、双后端兼容、已部署应用无感切换。
- 查询缓存、缓存抽象、Redis 可选支持或其他缓存后端。
- 独立 MQ、替换邮件 outbox、承诺邮件恰好发送一次。
- 多 API 实例作为交付目标、选主、分布式调度和集群设施。
- 备份及恢复功能、恢复流程改造或新增备份恢复说明。
- 降低会话活动时间记录精度、改变会话续期或过期规则。
- 项目目录重构、更换框架、数据库多选生成器、JWT 改造和无关 UI 修改。
- 数据库扩展、外部调度服务、全站 DDoS 防护或未经验证的性能承诺。

## Further Notes

- 规格来自已收敛的讨论，不代表已实施或已压测。此次发布仅新增规格。
- 最新范围优先于早期讨论：限流策略扩展、优雅停机修复和查询缓存均不属于本轮。
- 技术复杂度集中于会话并发、双桶原子操作和安全清理。移除 Redis 的目标是减少运行依赖，不是声称 PostgreSQL 在所有负载下更快。
- 本轮不引入新领域术语，沿用现有在线用户、强制退出等定义；存储和部署决策不写入领域词汇表。
- 测试边界已在发布规格时向用户说明：现有 HTTP 集成测试为主，必要的 PostgreSQL 存储并发测试及生成器回归为辅；不为确认边界追加访谈，用户可在实施前审阅本节。
