# 邮件任务管理与可配置投递策略

Status: open
Labels: ready-for-agent
Implementation: not-started

## Problem Statement

管理员目前可以配置 SMTP，却无法集中查看系统邮件的投递进展、失败原因或发送尝试。SMTP 修复后，没有统一的入口批量重试失败邮件；不需要的邮件也无法主动删除。自动重试和清理策略隐藏在代码中，测试邮件又采用另一条直接发送路径，造成运维理解和处理上的不一致。

本项目是生成新项目的模板。本轮面向从头生成的项目，不要求兼容旧部署、迁移旧配置或照顾升级前的历史任务；这不意味着省略新项目运行后的数据保留、安全与运维功能。

## Solution

在“系统监控”中增加“邮件任务”，展示所有系统邮件任务，包括测试邮件。管理员可按收件地址、用途、状态、创建时间筛选，查看脱敏详情和每次发送尝试，并对失败任务执行单条或批量重试、对非发送中任务执行单条或批量物理删除。

任务只有待发送、发送中、等待重试、已发送、发送失败五种界面状态，不提供取消操作。失败记录存在且尚未删除或按保留策略清理，就保留发送原邮件所需内容，允许手动重试，不要求运维判断链接或验证码是否有效。重新发送不生成新凭据、不延长原凭据有效期，业务验证仍严格拒绝失效凭据。

系统设置中的邮件配置增加自动重试次数和邮件记录保留天数，默认分别为 9 次和 30 天。测试邮件先保存 SMTP 配置再提交，作为普通任务遵守同一套投递与重试规则；页面区分提交成功与发送成功。发送与重试均采用最新已保存的 SMTP 配置。

## Implementation Decisions

### 边界与现有模块

- 扩展现有认证邮件、系统邮件配置、事务型邮件队列、SMTP 适配、角色权限、操作历史和后台列表体系；不新增独立邮件平台或消息代理。复用现有 PostgreSQL 和后台查询/反馈模式。
- 覆盖邀请、密码重置、密码修改通知、更换邮箱验证码、邮箱更换通知和测试邮件。任务用途可扩展，但本轮不增加其他业务邮件。
- 系统监控二级菜单依次为在线用户、操作历史、邮件任务；系统设置仍位于一级菜单末尾。后台页面只保留一个主标题，不加说明性副标题或重复标题。
- 新增邮件任务 read/write 权限，write 对应重试和删除，不隐含 read；角色配置通过既有功能权限组合配套 read。超级管理员拥有全部能力。系统设置权限与邮件任务权限独立，服务端逐入口强制校验。
- 自动重试次数和保留天数属于系统设置中的邮件配置，沿用系统设置读取/修改权限及既有并发更新规则；不是邮件任务页面中的局部浏览器配置。

### 持久邮件与凭据权限分离

- 一条任务表达一封固定邮件，手动重试仍是同一任务的新发送轮次，不生成另一封业务邮件。持久化原收件地址、邮件用途、语言、重发所需的稳定内容和必要投递元数据；不在重试时通过当前用户或邀请资料重新拼出另一份内容。尤其邮箱更换通知必须保持原旧邮箱收件快照。
- 当前队列依赖密码重置、邀请和邮箱验证请求来重建正文，并会因权限消费、过期、级联删除而清除或丢失发信材料；这不足以实现本轮要求。重发内容必须独立于这些可消费或被替换的业务权限，不能仅在旧数据结构上增加列表接口。
- 邮件任务投递与验证码/链接验证分离。保留的失败任务可以补发原邮件，即使其中的链接或验证码已过期、被替换或使用；不得因为重发而创建新权限、恢复旧权限、延长到期时间或减少验证安全限制。验证端仍使用真实业务权限和原到期时间判断。
- 不把“验证码过期”做成管理员需要判断的重试条件，也不能沿用后台的旧过期/关联权限检查使界面重试成功却永远不会尝试投递。当前业务邮件的任务有效性、自动失效清理与关联删除逻辑必须一起审视，投递材料的存活由任务保留/删除策略决定，而不是凭据表的生命周期。
- 用户删除、邀请撤销/接受、密码重置消费以及邮箱验证码替换不得级联删除仍应保留的邮件任务及其重发材料。邮件记录不因此恢复任何已删除身份或授权能力。相应收件与身份展示采用历史快照，不串到后来同邮箱注册的新账号。
- 持久化发送内容可能包含凭据，应使用现有安全能力有界扩展加密存储并正确隔离用途；不可明文落入通用 JSON、操作日志、应用日志或管理读取响应。管理权限不提供解密正文能力。不要保存原 SMTP 密码或逐任务 SMTP 配置快照。
- 发送和重试使用最新已保存的 SMTP 连接及发送服务配置；邮件正文、原收件人和业务语言不因修正 SMTP 或切换界面语言而变化。投递采用既有至少一次语义，不宣称恰好一次或撤回已发送副本。

### 状态、轮次、尝试与并发

- 对外只有五种状态：待发送、发送中、等待重试、已发送、发送失败。不得暴露已取消作为第六种状态，也不提供取消 API 或按钮。
- 已发送仅表示 SMTP 服务接收，不是收件箱送达、阅读或回执。发送失败表示当前轮次终止；等待重试仍属于当前轮次。
- 沿用租约/原子领取和临时错误退避机制；可恢复的进程中断不能使任务永久卡在发送中。不得通过简单前端禁用按钮替代真实数据库互斥。
- 自动重试次数不含首次发送，默认 9，0 关闭自动重试；永久错误可提前结束。采用当前全局设置判断后续重试，无需配置版本兼容层。已经终止的任务不会因为改大次数自动恢复。
- 手动重试仅允许最终失败任务，原子开始新轮次并重新提供全局配置所允许的自动重试预算。任务累计尝试次数继续增加，不得用累计次数误判新轮次预算已经耗尽。
- 每次真实发送尝试保存尝试时间、结果和安全失败原因。轮次与尝试记录需要足够支持预算、累计展示、清理时间和并发一致性，但不要求暴露内部租约/密钥信息。
- 并发手动重试、发送领取、删除和自动清理必须对同一任务作出唯一合法决定。旧租约或旧轮次的迟到结果不能覆盖新状态或使已删除任务复活。
- 批量重试/删除逐任务遵守与单条相同的规则，支持部分成功并提供成功、跳过/失败数量及安全原因，不以一条冲突回滚其他独立任务。不允许无界批量、任意查询表达式或绕过既有数据库限流思想。

### 删除、保留与审计

- 有管理权限的管理员可物理删除非发送中任务；删除待发送或等待重试任务后不可再领取发送。正在发送的任务明确返回冲突并在界面禁用删除；需在同一持久化并发边界再次检查。
- 物理删除同时清除任务本身、加密重发内容、该任务所有发送尝试记录，不保留软删除行或列表占位。只保留独立操作历史中的安全审计摘要。删除不撤回 SMTP/收件人已有副本，也不承诺删除既有数据库备份。
- 自动清理只覆盖已发送、发送失败的终态任务，默认从最后一轮结束时间起保留 30 天。手动重试使任务重新活跃；新一轮结束后重新计算保留时间，不能沿用原创建时间立即清理。
- 清理分批有界执行，与发送和人工操作安全竞争，不阻塞正常投递；统一替代现有已发送/已取消固定 7 天、失败固定 30 天的分散策略。
- 重试、删除和投递策略设置修改接入既有操作历史，记录操作者、目标和结果等安全摘要；删除任务不删除这些审计记录。批量操作能辨认处理结果，但不复制正文、验证码、链接或未经脱敏的 SMTP 错误。自动尝试过程放在任务详情，不重复灌入管理员操作历史。
- 配置输入只接受有界整数；负数、小数、错误类型和异常大值应产生中英文可理解字段错误。0 只在自动重试次数中表示关闭，不为保留天数擅自添加永久保存或关闭清理语义。具体安全上限可按既有配置风格选择并通过契约测试固定。

### 测试邮件与 SMTP 配置交互

- 删除测试邮件使用未保存表单配置的旧直接发送语义。SMTP 配置先保存再测试；未保存修改需明确引导先保存，不能暗中发送另一份配置。
- 测试操作创建用途为测试的普通持久任务，返回已接受的任务标识/状态，不把入队成功返回为 SMTP 发送成功。不要一边同步发送一边再次入队造成双发。
- 测试任务与业务任务共用自动/手动重试、尝试记录、删除和保留策略，保留原有测试邮件的滥用防护，不新增临时密码留存。
- 配置页面可以观察自己提交测试任务的最小状态结果，即便操作者没有全局邮件任务读取权限；这不能绕过邮件任务列表与任意任务详情的独立权限。可以采用提交者限定状态查询等有界接口，不能为此隐式授予全局读取权限。
- 原邮件配置保存与测试反馈、客户端契约、前端测试和生成项目验收需要同步更新，不能只把后台调用替换成异步后保留“发送成功”的旧文案。

### 查询与前端契约

- 列表默认全部任务、创建时间倒序、稳定分页；支持收件地址、邮件用途、状态、创建时间范围筛选和发送失败快捷筛选。参数严格校验，查询有界并建立必要索引。
- 详情返回用途、收件地址、语言、状态、时间、累计尝试次数及尝试列表/失败原因；不得返回正文、验证码、完整邀请/重置链接、加密材料、SMTP 凭据或原始异常堆栈。
- 为五种状态、单条/批量反馈、删除确认、筛选、空态、加载与错误反馈提供一致中英文文案。失败提示应定位排障类别，使用明确脱敏/安全映射，不直接回显 SMTP 返回的任意字符串。
- 遵循既有严格 JSON、请求体大小、同源变更请求和活跃登录校验；角色撤权、停用或会话失效不能通过缓存绕过权限。
- 列表支持单选/多选批量操作；删除有明确确认反馈，发送中不可删除，不符合重试条件不可发起新轮次。状态可通过既有查询刷新方式更新，无需引入 WebSocket 基础设施。

## Testing Decisions

- 用户已确认测试边界：主要验收复用 Playwright + Mailpit，通过页面完成核心流程；真实 HTTP API + PostgreSQL 验证安全、事务、并发和清理边界；从实际生成的新项目验证交付，不要求旧部署兼容。
- 好测试断言外部行为与持久化可观察结果，不锁死私有函数、内部字段排列或只模拟 store 返回成功。优先既有 HTTP/浏览器入口；必要时复用现有 SMTP 测试适配器、受控时间与数据库夹具，不扩散新测试接缝。
- 第一条纵向路径：配置 SMTP 并保存 → 提交测试邮件 → 页面先显示已提交/投递状态 → 邮件任务查询 → Mailpit 收到邮件 → 已发送与一次尝试记录一致。验证测试邮件和业务邮件走同一流程。
- SMTP 临时失败/恢复路径：观察等待重试与尝试记录，达到配置次数后失败，修正已保存配置后单条/批量手动重试成功，累计次数保留而新轮次预算重新计算。覆盖 0 次、默认 9 次、永久错误提前停止、全局配置修改不自动恢复终态任务。
- 邮件凭据边界：通过邮件接收入口取得原密码重置/邀请链接或邮箱验证码；使其过期、消费或被替换后，仍可重试保留的失败邮件，接收内容与原邮件一致，但业务验证拒绝失效凭据。不得从业务秘密字段直接取码代替邮件验收。
- 使用真实权限角色验证无权限、只读、read/write、超级管理员及只有系统设置权限者的行为；系统设置人员只能查看自己提交测试的最小结果，不得越权读取其他邮件列表/详情。
- 真实 HTTP 与 PostgreSQL 测试覆盖严格参数/请求体、同源保护、API 无正文/凭据泄漏、原收件/语言快照、非发送中物理删除及其关联尝试/内容消失、独立审计保留、非法操作安全失败。
- 并发覆盖多实例领取、重复手动重试、领取与删除、发送中删除、批量部分冲突、手动重试与清理、旧租约迟到完成、进程中断后租约恢复。验证没有多个并行有效轮次、已删除任务复活或越权成功；保留至少一次投递的现实边界。
- 使用可控时间或一致的数据库时间夹具验证最后一轮结束后 30 天清理及新轮次重新计时，不通过实际等待 30 天或长时间睡眠验收，不削弱生产约束来迁就测试。
- 浏览器覆盖五种状态可理解展示、全部任务/失败快捷筛选、组合筛选与分页、中英文、批量结果、删除确认、详情安全内容、设置字段错误及未保存 SMTP 修改时先保存再测试的引导。
- 复用已有认证邮件 Mailpit 场景、个人设置 HTTP/PostgreSQL 与竞态测试、操作历史保留测试、系统设置组件/API 测试、真实 tarball 生成与首次运行门禁。随着新的任务模型替换旧投递规则，调整旧测试的业务断言，不通过删除核心安全用例获得通过。
- 常规验收包括后端测试/vet/build，前端 lint/typecheck/tests/build，生成器与打包测试、实际 tarball 首次初始化/登录及生成项目邮件管理主路径。完整运行启用的集成/浏览器测试，不将缺 DSN/Mailpit 导致的 skip 算作通过。
- 源码和 Git 操作本地完成；资源密集型测试在 Centaurus 明确隔离的工作区、Compose 项目、数据库和端口执行，并转发暴露的前后端/API 服务到本地。远端由父代理管理，使用字面量专用路径和非删除同步，不使用未验证的临时路径变量，不触碰其他项目或旧验证资源。Centaurus 不可用时先报告，不擅自转为重型本地执行。
- 测试报告、浏览器 trace/截图、日志与提交不得暴露邮件正文中的凭据、SMTP 密码或加密密钥；需要观察正文的验收在私有测试上下文完成并只报告安全结果。

## Out of Scope

- 接收邮件的收件箱、邮件营销、任意群发、模板编辑器、正文预览/导出、附件管理、外部邮件服务控制台。
- 邮件取消操作/取消状态、软删除、已删除任务占位、撤回 SMTP 或收件人已取得副本、清除数据库备份。
- 重试时生成新验证码/链接、延长凭据有效期、将管理员变成验证权限管理者、因凭据已失效而禁止补发原失败邮件。
- 单独的测试邮件自动重试规则、使用未保存 SMTP 表单快照发送、逐任务保存 SMTP 密码。
- 新 SMTP 加密传输策略、MFA/SSO、账号安全规则弱化、另建消息代理、WebSocket 进度基础设施、恰好一次投递保证。
- 旧部署平滑升级、旧邮件数据兼容层和旧配置迁移；不因新项目起步而省略未来运行期的数据保留。
- 推送、发布版本、变更与本功能无关的临时验证脚本、恢复或清理历史事故资源。
