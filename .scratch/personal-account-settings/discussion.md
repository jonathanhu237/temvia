# 个人账号设置与头像：讨论记录

Status: discussion-complete
Implementation: not-started

## 已确认

- 范围：本人头像上传/更换/移除、姓名修改、密码修改、登录邮箱更换。设备管理暂不纳入。
- 更换邮箱流程：输入当前密码，向新邮箱发送验证码，验证成功才替换登录邮箱。
- 不要求验证旧邮箱；验证完成前仍使用旧邮箱登录。
- 新邮箱被其他账号使用时不允许更换。
- 更换成功后向旧邮箱发送通知。
- 修改密码或成功更换邮箱后，所有设备的现有登录失效，包括当前设备，用户需重新登录。修改密码后用新密码，更换邮箱后用新邮箱和原密码。
- 仅修改姓名或头像不影响登录状态。
- 头像采用本地上传 → 拖动/缩放裁剪预览 → 保存；裁剪成正方形。支持移除并恢复姓名首字默认头像，不支持图片链接或第三方头像服务。
- 初次讨论要求侧边栏一级入口；该入口决定已被下方“入口迁移补充确认”取代。页面仍沿用系统设置页面风格和页内导航，将相关设置集中在同一页面。
- 页面分区确定为个人资料（头像、姓名）、外观与语言（主题、界面语言）、账号安全（更换邮箱、修改密码）。登录后移除顶部语言和主题快捷按钮；登录、找回密码等未登录页面仍保留切换入口。
- 官方产品资料调研后，用户确认：界面语言跟随账号；明暗主题仅作用于当前浏览器，默认跟随系统，支持浅色、深色和跟随系统，并注明“仅对当前浏览器生效”。不增加跨设备同步开关。
- 语言初始化最终方向：未登录时默认使用浏览器语言；受邀用户的初始账号语言取其邀请邮件实际使用的语言，后续由用户在个人设置自行切换。个人设置仅提供中文/英文，不提供“跟随浏览器”。不采用首次登录页面语言初始化受邀账号；不将管理员界面语言当作邀请邮件语言。
- 首位管理员以创建管理员时的页面语言初始化；升级前尚未保存语言的已有账号，以首次登录新版时的页面语言初始化一次，以后使用账号保存的语言。
- 未登录页面手动切换语言后在当前浏览器记住，刷新保留；没有手动选择时才采用浏览器语言。这份未登录偏好与登录后的账号语言分离，不覆盖账号语言。
- 头像展示于左下角账号区域、个人设置、用户列表和在线用户列表；无头像或移除后统一显示姓名首字。操作历史不增加头像。
- 比较数据库与 S3 后，用户确认本次头像使用 PostgreSQL 存储，不引入对象存储或通用文件上传能力。保存裁剪处理后的图片，不保留原始大图；输出规则见下。
- 头像通过同源图片 API 返回二进制内容并检查登录 Cookie，未登录用户不能访问。沿用用户列表和在线用户列表原有页面权限，不新增头像权限项；无头像时直接显示姓名首字。
- 各项独立保存：姓名点击保存；头像裁剪确认后单独保存；语言和主题选择后立即生效并保存；邮箱和密码各自独立验证、提交。不提供全页“保存全部”。
- 修改密码要求当前密码、新密码、确认新密码，沿用既有密码强度规则；忘记当前密码走邮件找回。成功后使所有设备重新登录，并发送密码修改通知邮件。
- 更换邮箱验证码为 6 位数字、10 分钟有效，60 秒后可重发；重发使旧验证码失效。连续输错 5 次后本次验证码失效，需要重新申请。验证完成前不占用新邮箱，提交时再次检查是否被其他账号使用。更换成功后旧邮箱收到的密码重置链接一并失效。不为这些规则增加管理配置项。
- 头像支持 JPG、PNG、WebP，文件最多 5 MB，不支持 SVG 或动图；裁剪后经后端校验统一保存为 256×256 PNG，不保留原图和照片元数据。各处展示沿用圆角方形，不增加格式/尺寸配置项。
- 邮件异常行为已确认：邮件服务可用性由部署管理员负责，沿用现有邮件发送/重试；未完成邮箱验证码验证就不更换邮箱，已成功修改的密码不因通知失败而撤销。
- 邮箱更换验证请求与登录会话、密码修改独立：退出、强制退出或修改密码不自动取消请求；提交验证码时仍必须登录同一账号。验证码仍遵守有效期、重发和错误次数规则；账号停用期间不能完成操作，账号删除或邮箱已更换后原请求失效。此决定取代先前建议的会话/密码变更即取消请求。
- 邮件管理已明确拆为独立规格，延后到下一个周期，本轮不展开、不实现。需求方向为查看邮件发送失败、配置修正后手动重发、取消不该发送的邮件；详细边界留到该周期讨论。本轮个人设置仍沿用现有邮件发送/重试机制，不新增邮件管理页面或告警机制。
- 操作历史记录姓名、头像、邮箱和密码修改，不记录密码、验证码或图片内容；语言和主题切换不记入操作历史。修改姓名/邮箱后，已有操作记录保留当时的姓名/邮箱，不改写历史。
- 按用户偏好一次讨论一个问题；讨论阶段不实施。讨论已完成，等待用户明确要求实施。
