# 个人设置：资料、头像、界面偏好与账号安全

Status: open
Labels: ready-for-agent
Implementation: not-started

## Problem Statement

当前后台只有共享的系统设置，用户无法在登录后集中管理自己的姓名、头像、登录邮箱和密码。账号区域显示姓名首字，用户列表显示通用人物图标，没有真实头像。语言和主题分散在顶部快捷入口，语言仅保存在浏览器，无法体现用户登录后的个人偏好。

使用者需要一个与系统设置风格一致、从头像下拉菜单进入的个人设置页面。用户应能够独立保存各项资料、安全地更换登录凭据，并清楚地区分账号语言、未登录页面语言以及仅对当前浏览器生效的主题。

本项目是自用后台模板，本轮不需要对象存储、设备管理、通用文件中心或邮件管理平台。应复用现有认证、数据库、邮件投递和操作历史能力，避免引入无关基础设施。

## Solution

在头像下拉菜单提供“个人设置”入口，面向所有已登录且可正常使用账号的用户，不依赖系统设置管理权限。沿用系统设置的一页分区、页内导航和响应式布局，集中提供：

- 个人资料：修改姓名，上传、裁剪、更换或移除头像。
- 外观与语言：中文/英文账号语言，以及当前浏览器的浅色、深色、跟随系统主题。
- 账号安全：更换登录邮箱、验证当前密码后修改密码。

各项独立提交，不提供全页“保存全部”。头像裁剪后存入 PostgreSQL，通过需要登录的同源图片接口读取，在账号区域、个人设置、用户列表和在线用户列表统一展示。

未登录页面以浏览器语言为默认值，记住该浏览器手动选择的访客语言；登录后使用账号保存的语言。受邀账号的初始语言来自其有效邀请邮件的语言，而非管理员界面语言；首位管理员和旧账号使用各自已确认的初始化规则。

更换邮箱必须验证当前密码和发送到新邮箱的验证码，不要求旧邮箱验证。邮箱验证请求独立于登录会话和密码修改，但完成验证时必须登录同一账号。修改邮箱或密码成功后，所有设备的旧会话失效，包括当前设备，必须明确重新登录。

## User Stories

1. As a 已登录用户, I want 从头像下拉菜单进入个人设置, so that 我能快速找到管理自己账号的入口。
2. As a 普通用户, I want 不依赖系统设置权限即可管理自己, so that 个人功能不会被管理员权限挡住。
3. As a 用户, I want 个人设置与系统设置保持相同风格, so that 我不必学习另一套交互方式。
4. As a 用户, I want 在同一页面通过页内导航定位资料、外观与语言、账号安全, so that 设置集中但容易浏览。
5. As a 手机用户, I want 个人设置在窄屏上仍可正常填写和操作, so that 我不必切换到电脑才能管理账号。
6. As a 用户, I want 每项设置独立保存, so that 未填完的安全表单不会阻止我修改头像或姓名。
7. As a 用户, I want 修改自己的姓名并明确保存, so that 后台能够显示正确的个人身份。
8. As a 用户, I want 姓名沿用现有验证规则, so that 初次创建和后续修改不会出现矛盾。
9. As a 用户, I want 姓名保存失败时保留输入并显示可理解的反馈, so that 我可以修正后重试。
10. As a 用户, I want 上传本地图片作为头像, so that 其他有权访问相关页面的用户更容易识别我。
11. As a 用户, I want 拖动和缩放图片后预览正方形裁剪结果, so that 我能够控制头像的构图。
12. As a 用户, I want 取消裁剪时保留原头像, so that 试选图片不会意外修改资料。
13. As a 用户, I want 裁剪确认后单独保存头像, so that 更换头像无需提交其他设置。
14. As a 用户, I want 使用 JPG、PNG 或 WebP 图片, so that 常见图片格式都能用于头像。
15. As a 用户, I want 文件超过 5 MB、格式不支持或图片损坏时得到明确提示, so that 我知道如何重新选择图片。
16. As a 用户, I want 移除自定义头像后恢复姓名首字头像, so that 不想展示照片时仍有清晰的身份占位。
17. As a 用户, I want 账号区域、个人设置、用户列表和在线用户列表使用一致的头像样式, so that 同一个人在不同页面能够被一致识别。
18. As a 用户, I want 更换头像后看到新版本而不是旧缓存, so that 我能确认保存结果。
19. As a 用户, I want 头像不能被未登录访客通过图片链接访问, so that 账号图片不是公开资源。
20. As a 部署者, I want 头像存入 PostgreSQL 并跟随数据库备份, so that 不必配置对象存储或额外持久上传目录。
21. As a 部署者, I want 只保留处理后的头像而不保留原始大图, so that 小规模头像不会演变为通用文件存储负担。
22. As a 用户, I want 个人设置中的界面语言只有中文和英文, so that 选项清晰且没有额外的自动模式。
23. As a 受邀用户, I want 初始账号语言与我的邀请邮件语言一致, so that 激活后有可预期的界面语言。
24. As a 受邀用户, I want 后续可以自行选择另一种界面语言, so that 邀请方提供的初始值不会永久限制我。
25. As a 首位管理员, I want 创建账号时的页面语言成为初始账号语言, so that 没有邀请邮件也能正确初始化偏好。
26. As a 升级前已有账号的用户, I want 第一次登录新版时仅初始化一次账号语言, so that 旧账号平滑过渡且后续不会被重新覆盖。
27. As a 用户, I want 登录后使用账号保存的语言, so that 换设备仍保持自己的明确选择。
28. As a 未登录访客, I want 系统默认匹配浏览器支持的语言, so that 首次打开页面时无需先寻找语言设置。
29. As a 未登录访客, I want 手动切换语言后当前浏览器记住选择, so that 刷新页面不会立即恢复成另一种语言。
30. As a 用户, I want 访客语言和账号语言互不覆盖, so that 登录页操作不会偷偷改变我的个人偏好。
31. As a 使用同一浏览器切换账号的用户, I want 每次登录加载对应账号的语言和资料, so that 不会继承前一个账号的偏好或身份内容。
32. As a 用户, I want 语言选择后立即生效并保存, so that 不需要额外点击全页保存。
33. As a 用户, I want 主题只作用于当前浏览器, so that 在电脑上选择浅色不会改变手机上的外观。
34. As a 用户, I want 主题提供浅色、深色和跟随系统并默认跟随系统, so that 我可以明确选择或随设备外观变化。
35. As a 用户, I want 主题设置注明“仅对当前浏览器生效”, so that 不会误以为它像语言一样跨设备同步。
36. As a 用户, I want 登录后的语言和主题入口集中在个人设置, so that 顶部不再出现重复快捷入口。
37. As a 未登录访客, I want 登录、找回密码等页面仍有语言和主题切换入口, so that 登录前也能调整可读性。
38. As a 用户, I want 输入当前密码、新密码和确认新密码来修改密码, so that 持有一个登录页面不足以悄悄改变我的凭据。
39. As a 用户, I want 新密码沿用既有强度要求, so that 密码设置规则一致。
40. As a 忘记当前密码的用户, I want 继续使用既有邮件找回流程, so that 个人设置不需要另造找回机制。
41. As a 用户, I want 修改密码后所有设备重新登录, so that 旧会话不能继续使用。
42. As a 用户, I want 收到密码修改通知邮件, so that 我可以察觉不属于自己的修改。
43. As a 用户, I want 更换邮箱时先验证当前密码, so that 他人不能仅靠临时获得的会话改变我的登录地址。
44. As a 用户, I want 验证码发到新邮箱而不要求旧邮箱验证, so that 旧邮箱不可用时仍能更换。
45. As a 用户, I want 验证完成前继续使用旧邮箱登录, so that 未完成的请求不会改变账号入口。
46. As a 用户, I want 输入 6 位数字验证码且看到 10 分钟有效期, so that 更换流程简单明确。
47. As a 用户, I want 60 秒后可以重新发送验证码, so that 没收到邮件时可以重试而不能无节制重复发送。
48. As a 用户, I want 重发后旧验证码失效, so that 不会有多份互相混淆的有效验证码。
49. As a 用户, I want 连续输错 5 次后必须重新申请验证码, so that 验证码不能被无限尝试。
50. As a 用户, I want 新邮箱在验证前不被我的请求占用, so that 未完成请求不会锁住别人可合法使用的地址。
51. As a 用户, I want 完成验证时重新检查邮箱占用, so that 并发操作不会让不同账号获得相同登录地址。
52. As a 用户, I want 退出、被强制退出或修改密码后，邮箱验证请求仍按原有效期存在, so that 独立操作不会无故取消我的验证。
53. As a 用户, I want 重新登录同一账号后能继续尚未失效的邮箱验证, so that 邮箱验证请求不被某一次会话绑定。
54. As a 用户, I want 验证码只能在已登录的同一账号上使用, so that 仅拿到验证码的人不能改变别人的邮箱。
55. As a 用户, I want 账号停用期间不能完成邮箱更换, so that 邮箱验证不能绕过停用限制。
56. As a 用户, I want 账号删除或邮箱已更换后旧请求失效, so that 过期的账号操作不能在未来重新生效。
57. As a 用户, I want 更换邮箱成功后使用新邮箱和原密码重新登录, so that 登录身份变化清晰且不需要同时修改密码。
58. As a 用户, I want 更换邮箱成功后所有旧会话和旧邮箱的密码重置链接失效, so that 旧访问途径不再控制账号。
59. As a 用户, I want 更换成功后旧邮箱收到通知, so that 原邮箱持有人能知道账号发生了变更。
60. As a 用户, I want 收不到验证码时保持旧邮箱不变, so that 邮件故障不会使账号处于半完成状态。
61. As a 用户, I want 已完成的密码修改不因通知邮件发送失败而被撤销, so that 账号安全操作不依赖 SMTP 当场可用。
62. As a 部署管理员, I want 新邮件沿用现有发送与重试机制, so that 本轮不引入另一套邮件基础设施。
63. As a 有操作历史读取权限的管理员, I want 看见姓名、头像、邮箱和密码修改的操作结果, so that 可以追溯账号变化。
64. As a 用户, I want 操作历史不保存密码、验证码或图片内容, so that 追溯行为不会泄露敏感材料。
65. As a 管理员, I want 用户改名或更换邮箱后旧操作记录仍保留当时身份, so that 历史不会被后续资料修改改写。
66. As a 用户, I want 语言和主题切换不进入操作历史, so that 日常偏好调整不会造成无意义的记录噪声。
67. As a 维护者, I want 新字段、接口、权限边界和迁移得到完整测试, so that 个人设置不会破坏邀请、找回密码、用户生命周期或模板首次安装。

## Implementation Decisions

### 页面与交互

- 个人设置仅在侧栏底部头像下拉菜单提供入口，置于“退出登录”上方，移除原侧栏一级入口；桌面展开、折叠侧栏和移动端使用相同方案。系统设置继续保持在一级菜单末尾。
- 此入口迁移取代先前保留一级侧栏入口的决定。保留 `/personal-settings` 地址、现有页面内容和访问权限，不拆出外观、安全等菜单子入口。当前为个人设置页时菜单项显示选中态；移动端点击后关闭侧栏并进入个人设置。
- 页面只有一个主标题，不增加说明性副标题或重复主标题。分区为个人资料、外观与语言、账号安全，采用现有系统设置的页内定位导航，而非新增多级子页面。响应式、键盘操作、焦点和 reduced-motion 行为沿用现有规范。
- 所有正常登录用户可管理自己的设置，不要求系统设置或用户管理权限，不新增可分配的个人设置权限项。本轮不增加管理员修改其他人姓名、头像、邮箱或密码的能力。
- 姓名显式保存；头像裁剪确认后单独保存、移除为独立操作；语言和主题选择后立即生效并保存；邮箱和密码使用各自独立表单和提交按钮。不能用一个全页表单耦合不同操作。
- 沿用现有姓名规范化/长度/控制字符规则、密码规范化及强度规则、邮箱规范化与占用判定。保存失败时保留可重试的非敏感草稿，反馈使用现有双语错误与成功提示机制，不新增全局警告系统。
- 资料保存成功后更新当前页面和账号区域的数据；其他列表在其既有刷新/重新请求时获取新资料，不引入新的实时推送服务。操作切换与请求完成须避免把前一个账号的数据写入后一个账号的缓存。

### 头像

- 支持本地 JPG/JPEG、PNG、WebP，文件上限 5 MB，不支持 SVG 或动图。前端选择阶段和服务端接收阶段都验证各自输入，不能只信扩展名、浏览器 MIME 或前端裁剪结果。
- 上传交互提供拖动/缩放、正方形裁剪、预览和确认；取消不改变保存状态。服务端解码验证后输出固定 256×256 PNG，重新编码去除原始照片元数据，不保存原始大图。解码同时需要有界尺寸/像素预算，避免压缩体积小但像素异常大的图片耗尽资源；沿用现有系统图标的有界校验思路，不将内部安全预算做成用户设置。
- 图片二进制保存在 PostgreSQL，与用户 ID 关联，优先与普通用户列表投影分离。列表和当前身份接口只返回头像存在性、版本或读取位置等轻量信息，不携带 Base64/完整图片。
- 更换原子替换已保存头像，失败保留旧头像；移除删除当前头像数据；删除用户清除头像内容，不给已删除身份保留照片。现有账号迁移后默认没有自定义头像。
- 读取走同源图片 API，返回正确图片 Content-Type，并执行有效登录校验。所有网络读取路径（包括缓存条件请求）都不能绕过会话验证；不得使用公共缓存或公开静态文件路径泄露头像。浏览器已经取得的图片无法被追溯撤回，不把访问控制描述为撤销已下载图片。
- 沿用现有列表访问权限，头像本身不新增权限项。当前范围是“已登录才可读头像”，而非额外建立新的逐用户头像授权体系；本人修改接口必须从会话确定目标账号，拒绝修改他人头像。
- 无头像、移除或图片加载失败时使用姓名首字占位，正确处理 Unicode 首字符，不截断代理对/组合字符。各处保持圆角方形，展示于账号区域、个人设置、用户列表和在线用户列表；不在操作历史增加头像。
- 头像版本用于防止替换后继续显示旧图；缓存策略不得破坏登录后可见、退出后新请求不可见的约束。系统图标仍是独立概念，其公共读取和管理权限不因复用图像校验而改变。

### 账号语言、访客语言与主题

- 账号界面语言只允许中文和英文，无“跟随浏览器”选项。账号语言持久化在用户资料中，不从管理员当前界面、IP 或后续浏览器语言猜测覆盖。
- 接受邀请创建用户时，在账号创建事务中从该次有效邀请的语言初始化账号语言。邀请重发可能改变有效邀请及其邮件语言，应使用最终被接受的邀请语言，不使用已经失效的旧邮件或届时系统默认值重新推断。
- 首位管理员以初始化页面的当前语言创建；已有账号可保留“尚未初始化语言”的过渡状态，在首次成功登录新版时以当时页面语言初始化一次。不能在失败登录时写入，也不能把所有旧账号在迁移时统一强制设为中文或英文。并发首次登录不得覆盖已完成的初始化或随后手动设置。
- 登录后优先应用服务端账号语言；主动切换保存成功后成为该账号的偏好，其他设备在后续登录或正常加载账号设置时使用它，不要求实时推送到所有已打开的页面。语言保存失败不能伪装成已同步成功，应保留清晰反馈并使显示与最终保存状态一致。
- 访客语言单独处理：已手动选择则使用当前浏览器保存的访客偏好，否则按现有浏览器语言匹配规则选择中文/英文，不支持时保留现有英文回退。登录、找回密码、初始化、接受邀请等未登录页面保留语言切换入口。
- 应区分“应用账号语言”与“用户修改访客语言”，不能复用一个无条件写 localStorage 的函数而相互覆盖。退出后恢复访客语言规则；切换账号时清除/隔离前一个账号的资料及语言缓存。访问已知账号之前的语言与登录后明确账号偏好不同，允许发生必要的一次切换，不承诺永远无切换。
- 界面语言不改变系统默认邮件语言。新增验证码、密码修改通知、邮箱更换通知沿用系统邮件语言策略，在创建具体邮件任务时固定其语言；系统名称仍保持语言中立。
- 主题仅存当前浏览器，支持浅色、深色、跟随系统，默认跟随系统，保留浏览器已有明确选择。设置注明“仅对当前浏览器生效”，不持久化为账号字段、不增加跨设备同步开关。跟随系统时响应该浏览器环境的系统外观变化。
- 登录后移除顶部语言和主题快捷按钮，统一在个人设置调整；未登录页面保留现有偏好入口。页面语言切换同步文档语言及相关已有 i18n 行为，不改变系统默认邮件语言或全局系统名称。

### 修改密码

- 新增已登录本人修改密码操作，输入当前密码、新密码及确认新密码；服务端校验当前密码和新密码强度，前端处理确认一致性，不仅靠前端验证保护请求。复用现有密码哈希及并发限制，不创造弱化的密码路径。
- 成功变更密码与使所有既有会话失效在同一事务性安全操作中完成；清理当前会话 Cookie/前端认证状态，提示后进入登录页，不自动发放替代会话。失败不能改变密码、撤销合法会话或报告成功。
- 既有密码找回权限按当前密码变更语义失效，避免旧找回链接再次覆盖新密码；但不能因此一并删除尚有效的邮箱更换请求。这两类验证权限用途不同。
- 发送密码修改通知，沿用现有邮件队列能力。SMTP 暂时不可用不能撤销已完成的密码变更；不把同步 SMTP 成功当作修改成功的前提，也不为本轮增加邮件告警或管理页。

### 更换登录邮箱

- 请求验证码时必须已登录本人并验证当前密码；提交新邮箱后发码到新邮箱，不向旧邮箱发送验证步骤。完成前账号当前邮箱和登录方式保持不变，不提前占用待验证的新邮箱。
- 验证码为安全随机的 6 位数字，10 分钟有效；60 秒内不能重复发码；每个有效请求连续输错 5 次即失效，重新申请才能继续；重发原子替换旧码，旧码立即失效，不能通过创建多个并行请求规避同一账号的重发限制。
- 待验证请求持久化关联账号、申请时的旧邮箱、新邮箱、独立请求标识/代次、验证码校验材料、到期时间、重发时间及剩余尝试等必要状态。它不是登录会话的一部分，不能以会话 ID 或 auth version 一变化就作废；退出、强制退出和密码修改/找回造成的会话失效不自动取消请求。
- 完成操作始终要求当前有效登录，且会话账号与请求所属账号相同；重新登录同一账号可继续未过期请求，接口不得凭验证码匿名换邮箱。停用期间拒绝操作；账号删除、邮箱已更换、验证码过期/耗尽/替换/消费后不能继续使用。
- 仅向本人返回继续验证需要的安全状态，不返回验证码、校验材料或其他账号的请求。允许重新登录后恢复当前请求的交互，不要求用户记住某个已退出页面内存中的状态。
- 对验证码校验、尝试次数递减、重发替换和一次性消费使用事务/并发控制。多个相同或不同请求竞争完成时，只能有一个成功，不得突破错误次数或重发间隔。
- 验证码不得明文进入业务记录、日志或 API 读取响应，也不能仅对六位码做容易离线穷举的无密钥摘要。复用既有安全密钥/加密能力时必须进行用途隔离；为异步邮件投递保存的验证码材料应得到与现有凭据邮件相当的保护，不新增面向用户的密钥/验证码规则配置页面。
- 发码和校验沿用既有数据库限流、严格 JSON/请求体上限及同源变更请求保护思路，不能因新建端点绕过基础滥用防护。产品固定规则保持 10 分钟、60 秒和 5 次，不增加管理配置项。
- 发码前可检查明显占用，但最终成功事务必须再次根据 canonical email 检查并发占用，包含停用但尚未删除的账号。与既有邀请创建/接受的邮箱唯一性规则协调，不能通过自助改邮箱打破现有跨账号/邀请的邮箱占用不变量；待验证邮箱请求本身不构成预留。
- 成功事务更新用户邮箱及规范化索引、消费/作废相关邮箱更换请求、使全部旧会话失效、撤销旧邮箱的密码找回权限及待投递的旧重置邮件。账号 ID、角色、姓名、头像和密码不变，用户用新邮箱与原密码重新登录。
- 更换成功后的通知必须送到旧邮箱。旧收件地址需要在操作时固定，不能在投递时读取已经更新的用户邮箱而发到新地址。邮件语言和内容也不能意外把验证码或密码带入通知。
- 邮箱变更验证请求的独立性，与成功更换后撤销所有会话是不同规则，二者都必须成立。不能因为复用现有密码重置/用户生命周期清理函数而将它们混同。

### 邮件与操作历史

- 本轮新增邮件用途仅为个人设置所需验证码和账号安全通知，复用 PostgreSQL transactional outbox、现有 SMTP 配置与发送/重试机制，不引入消息代理或通用邮件管理平台。
- 现有邮件队列没有任意收件人快照和通用验证码任务，应按新增邮件用途有界扩展其持久化、校验和投递逻辑；不能把验证码错误塞进邀请或密码重置权限而继承不合适的失效规则。
- SMTP 配置修正可供后续合格任务重试使用；过期、已替换或已消费的验证码任务不得作为有效验证继续投递。已被 SMTP 接收的邮件无法撤回；迟到或重复邮件中的失效验证码必须由验证端拒绝。
- 沿用既有至少一次投递语义，不承诺邮件恰好投递一次。用户未收到有效验证码就不能更换邮箱；通知投递失败不回滚已完成的密码或邮箱修改。邮件服务可用性由部署管理员负责。
- 姓名、头像、邮箱和密码的实际修改操作接入既有操作历史结果记录机制，保持既有权限和保留策略；不将发送验证码本身误记为邮箱已更换。记录足以识别动作、操作者、目标、结果的安全摘要，不保存密码、验证码、图片内容或敏感校验材料。
- 不记录语言和主题切换。已有操作记录中的姓名、邮箱保留当时快照，用户后续修改资料不能批量改写历史。操作历史不新增头像。

### 数据库、接口和交付

- 扩展用户资料投影与严格前端契约，添加账号语言、头像轻量元数据及个人设置所需读取/更新能力；普通列表不携带图片或秘密。具体路径和表名由实施时遵循现有模块边界确定，不在规格固定内部文件布局。
- 为账号语言、头像、独立邮箱更换请求和新增邮件用途提供完整正向/逆向迁移、必要约束和索引；与当前 schema readiness 检查和打包预检同步。迁移应保留已有账号、权限和历史；逆向迁移须明确数据丢失/拒绝条件，不能静默恢复旧凭据或绕过安全状态。
- 资料/语言保存不能复用会导致全设备退出的安全版本更新路径；不同设置独立保存不能丢失彼此更新。涉及邮箱、密码、验证码及旧权限失效的状态变更必须保证原子性和冲突反馈。
- 保留生成项目的独立性，不引入 Temvia 运行服务。新页面、契约、资源、依赖和迁移都必须进入实际发布 tarball，并保持独立生成、容器构建、数据库迁移及首次登录门禁可用。

## Testing Decisions

- 测试方案依据已确认产品行为拟定，优先复用现有入口，不追加用户访谈。以浏览器可见流程为最高层验收，以现有认证/个人设置 HTTP API 加真实 PostgreSQL 验证安全及并发边界；邮件使用现有 Mailpit/邮件适配器测试方式。单纯私有函数或内部字段快照不能替代用户行为验证。
- 入口迁移验收：侧栏主导航不再显示个人设置；头像下拉中个人设置位于退出登录上方，当前页有选中态；覆盖桌面展开/折叠侧栏及移动端，移动端点击后侧栏关闭；原地址直接访问、页面内容与权限边界保持不变。
- 第一条纵向验收路径：已登录普通用户从头像下拉菜单进入个人设置，独立修改姓名/头像/语言/主题，刷新后确认结果；不具有系统设置权限的用户也可使用，且不能修改他人账号。
- 复用现有设置页组件、认证表单、API mock、错误翻译与主题/i18n 测试，覆盖独立保存、失败保留草稿与重试、即时偏好变化、顶部入口迁移、页内导航、窄屏和键盘操作。不要绑定易变首页文案或重复实现生产校验逻辑作为预期值。
- 头像端到端覆盖选图、拖动/缩放裁剪、取消、保存、替换、移除、刷新及四处展示；验证无头像回退和 Unicode 姓名首字。服务端测试覆盖不支持格式、伪造 MIME/扩展名、损坏数据、动图、超大字节/像素输入、固定输出尺寸、去除元数据和失败保留旧图。
- 头像安全通过实际图片请求验证：匿名、已退出、已撤销或停用会话不能获得图片；有效登录可读；写接口不能越权；缓存/条件请求不绕过认证。验证用户列表响应不包含图片数据和秘密，用户删除后不遗留可访问头像。
- 语言使用至少两个独立浏览器上下文与不同浏览器语言验证：受邀初始化取有效邀请邮件语言而非管理员界面或接收者浏览器；邀请重发改变语言后以最终有效邀请为准；首位管理员取初始化页面语言；旧账号首次成功登录初始化一次，并发登录不覆盖后续设置。
- 覆盖访客默认语言、手动选择后刷新记忆、登录后账号优先、退出后访客规则恢复、同浏览器切换账号不串号。对不支持的浏览器语言维持现有英文回退。账号界面语言变化不改变系统默认邮件语言或系统名称。
- 主题验证仅当前浏览器持久化、另一浏览器不受影响；默认跟随系统并响应系统明暗变化。选择语言/主题即时生效，语言写入失败显示失败而不是伪装同步成功。
- 密码通过真实认证 API 验证当前密码错误、新密码不合规、确认不一致的 UI 反馈及成功修改。使用两个有效会话确认成功后全部失效，旧密码不能登录、新密码可以，通知通过现有邮件入口观察；姓名、头像、语言修改不撤销会话。
- 邮箱验证使用真实数据库与可控时间/既有测试时钟验证六位码、10 分钟边界、60 秒重发、5 次错误上限、新码替换旧码及一次性消费。不得用实际等待十分钟作为主要测试手段，不通过读取业务验证码秘密代替邮件接收验收。
- 覆盖关键独立性回归：申请后退出再登录同一账号可继续；强制退出后重新登录可继续；修改密码或完成密码找回后用新密码登录仍可继续；匿名或其他账号即使持有正确验证码也不能完成；停用期间拒绝，删除或邮箱已更换后旧请求无效。
- 并发测试覆盖重发与旧码验证竞争、多个正确码提交、失败次数竞争、多个账号争用目标邮箱以及与邀请创建/接受竞争。最终只能产生合法唯一结果，不能重复消费或绕过额度，失败事务不能部分改邮箱/撤销会话。
- 邮箱成功验收确认旧邮箱不能再登录、新邮箱与原密码可登录，所有旧会话失效，旧密码重置链接不可用，通知实际送往旧地址；失败、超时、邮箱冲突或邮件未送达时账号仍保留旧地址。
- SMTP 不可达时验证通知任务按现有策略处理，已成功修改不回滚；验证码到期/替换后验证端拒绝迟到邮件中的旧码。必要邮件投递信息从 Mailpit 或邮件适配器观察，不在测试报告、截图、浏览器 trace 或持久日志暴露密码/验证码/密钥。
- 操作历史通过既有查询入口检查资料/安全修改结果、敏感字段缺失、语言/主题没有记录，以及姓名/邮箱修改不改写旧快照。不要把内部 outbox 行当成用户可见操作历史。
- 执行现有 Go、前端、生成器、Git、打包与首次启动回归。数据库测试显式使用隔离且完整迁移的 PostgreSQL，不能将缺少 DSN 导致的跳过计作通过；保留邀请、找回密码、停用/恢复/删除及所有设备会话失效相关集成测试。
- 新功能的浏览器验收复用现有 Playwright 环境及 Mailpit，不要求把所有历史 E2E 都改为发布门禁。至少从实际生成项目验证新功能必要资源、迁移与核心用户流程，保持现有准确 tarball 的首次初始化/登录门禁通过。
- 验证遵守本地源码权威和 Centaurus 执行工作流：源码/Git 操作本地，资源密集型测试在明确隔离环境进行，暴露服务端口转发本地验收。远端同步使用经检查的专用明确路径，不使用依赖临时路径文件的未校验变量，也不对不确定目标使用删除同步；不能触碰其他项目或既有数据库。

## Out of Scope

- 邮件管理页面、发送记录检索、管理员手动重发/取消、邮件失败告警及相关新权限；已确定下周期单独讨论和立规格。
- 本人的设备列表、单设备退出、设备管理中心；本轮只实现已确认的安全修改后全设备失效。
- 管理员代替他人修改资料、密码、邮箱或头像；重新设计用户管理/角色权限模型。
- 对象存储、S3、持久上传目录、通用文件中心、头像外链、第三方头像服务、原图保留、SVG/动图头像。
- 头像尺寸/格式/验证码策略的管理配置界面，或额外的跨设备同步开关。
- 语言新增“跟随浏览器”个人选项、主题跟账号同步、按个人界面语言改变系统邮件语言。
- SMTP 传输加密策略改造、登录时间差修复、MFA、SSO、无密码登录或匿名验证码换邮箱。
- 因退出、强制退出或修改密码而自动取消邮箱验证请求；这与用户确认的独立性相违背。
- 全局通知中心、恢复已取消的后台警告系统、实时跨设备推送架构。
- 修改历史身份快照、为操作历史增加头像、保留用户删除后的头像照片。
- 公开发布、自动提交或推送；当前请求只授权整理规格，不授权实现与发布操作。

## Further Notes

- 依据本轮已完成讨论和当前代码基线 7056aba 整理。用户明确选择两种个人语言、邀请邮件语言初始化、访客语言独立记忆，以及邮箱验证请求与登录/密码操作独立；前期被否决的替代建议不属于本规格。
- 现有系统图标已经具备图片解码校验与 PostgreSQL 存储先例，但其公开读取、系统配置权限和单例数据模型不能直接照搬为用户头像权限与存储语义。
- 当前登录状态投影、列表和前端 schema 较严格；实施须同步契约，不能只在页面添加头像字段。当前语言切换函数会写浏览器存储，账号语言接入时必须拆清“应用账号值”与“保存访客选择”的语义。
- 现有邀请重发会替换邀请权限并应用当时系统默认邮件语言；账号初始化应绑定最终有效邀请的语言。现有 outbox 在投递时关联当前用户数据，旧邮箱通知需要显式保存旧收件人，不能只加一个邮件类型而忽略数据生命周期。
- 既有账号安全版本同时用于会话失效；邮箱验证请求不能直接依赖该版本。修改邮箱成功必须使会话失效，但这不意味着发起邮箱验证与会话共生共灭。
- 邮件服务运维责任归部署管理员，不意味着新代码可以绕过验证或悄悄回滚已成功的安全操作；本轮只要求沿用既有发送/重试与明确操作结果，不扩展邮件运营管理功能。
- 本规格在本地 Markdown issue tracker 中标为 ready-for-agent，表示可据此规划实施与测试，不表示已经实现、验收、提交或发布。测试组织是基于现有入口的规格建议，未将未讨论的具体文件布局或实现技术伪装成用户已指定的要求。
