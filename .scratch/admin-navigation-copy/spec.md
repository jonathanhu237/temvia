# 后台导航、强制退出文案与标题规范

Status: resolved
Triage: ready-for-agent
Testing seams: existing-real-browser-e2e
Implementation authorization: explicitly-authorized-via-implement-loop

## Problem Statement

后台把需求讨论中的口语“踢下线”直接展示为产品文案，出现在按钮、确认框、反馈、权限名称和操作历史中，语气不符合用户期望。

在线用户位于“用户与权限”下，操作历史单独占据一级菜单。同样用于了解系统使用情况的两个功能被分散，查找和切换不直观。

页面再次出现说明性副标题，在线用户的卡片还重复展示页面标题。重复文字增加视觉噪声，也违背全后台简洁、一致的标题规范。

## Solution

管理员终止用户所有设备登录的正式产品用语统一为“强制退出 / Force sign out”。确认框说明目标用户、所有设备均会退出以及可以重新登录；对自己执行时明确当前页面也会退出。

将“在线用户”和“操作历史”放入“系统监控”一级菜单，按此顺序排列。“用户与权限”保留用户、邀请、角色，“系统设置”继续位于一级菜单末尾。

在全后台落实统一标题规范：每个页面只保留一个页面主标题，删除说明性副标题和重复标题。该调整覆盖现有页面，不只修正在线用户页面。

## User Stories

1. 作为管理员，我希望操作按钮使用“强制退出”，以便看到正式、清楚的产品用语。
2. 作为管理员，我希望确认框采用与按钮一致的术语，以便确认自己正在执行什么操作。
3. 作为管理员，我希望确认框展示目标姓名或邮箱，以便核对操作对象。
4. 作为管理员，我希望确认框说明所有设备都会退出，以便理解操作影响。
5. 作为管理员，我希望确认框说明用户可以重新登录，以便理解强制退出与禁用账户的区别。
6. 作为管理员，我希望强制退出自己时看到当前页面也会退出的提示，以便提前理解当前操作的结果。
7. 作为管理员，我希望执行中、成功和失败反馈采用一致的正式用语，以便理解操作状态。
8. 作为权限配置者，我希望角色配置中的操作权限也使用“强制退出”，以便准确配置相关能力。
9. 作为操作历史查看者，我希望事件名称和筛选项使用“强制退出”，以便将记录与界面操作对应起来。
10. 作为操作历史查看者，我希望已有的相关记录也显示新的事件名称，以便历史记录和新记录保持一致。
11. 作为登录用户，我希望个人菜单中的主动退出继续叫“退出登录”，以便区分个人退出与管理员执行的强制退出。
12. 作为英文界面用户，我希望管理操作统一使用“Force sign out”，以便中英文具有一致的含义。
13. 作为管理员，我希望通过“系统监控”找到在线用户和操作历史，以便集中查看当前登录状态与历史操作。
14. 作为管理员，我希望在线用户排在操作历史之前，以便按当前状态、历史记录的顺序浏览。
15. 作为管理员，我希望这两个功能只在新的分组中出现，以便避免重复导航入口。
16. 作为用户与权限管理者，我希望原分组保留用户、邀请、角色，以便继续按原有方式管理账户与授权。
17. 作为管理员，我希望系统设置仍位于一级菜单末尾，以便保留已熟悉的导航顺序。
18. 作为仅能查看在线用户的人员，我希望系统监控只展示在线用户入口，以便菜单反映自己的权限。
19. 作为仅能查看操作历史的人员，我希望系统监控只展示操作历史入口，以便直接找到可用功能。
20. 作为没有这两项查看权限的人员，我希望不出现空的系统监控分组，以便导航保持清楚。
21. 作为管理员，我希望进入子页面时能看出当前分组和当前页面，以便理解自己在导航中的位置。
22. 作为通过已有链接进入后台的用户，我希望菜单调整后链接仍能打开相同页面，以便继续使用收藏和已有入口。
23. 作为后台用户，我希望每个页面只有一个页面主标题，以便快速识别当前页面。
24. 作为后台用户，我希望不再看到主标题下的说明性副标题，以便页面更加简洁。
25. 作为后台用户，我希望卡片不再重复页面主题标题，以便避免重复阅读相同内容。
26. 作为用户、邀请和角色页面的使用者，我希望这些页面也遵守统一标题规范，以便改动覆盖整个后台。
27. 作为操作历史和系统设置的使用者，我希望各页面标题层级一致，以便切换页面时保持相同的阅读习惯。
28. 作为键盘或辅助技术使用者，我希望菜单分组和页面标题仍能被清楚识别，以便正常导航和操作。
29. 作为窄屏设备使用者，我希望菜单分组、标题和操作文案在较窄视口中仍然清楚可用，以便完成同样的管理任务。
30. 作为中英文界面的使用者，我希望切换语言后菜单、操作和标题规范都一致生效，以便获得完整的本地化体验。

## Implementation Decisions

- 采用已确认的领域用语 Force sign-out（强制退出）。管理操作的中文显示不用“踢下线”，英文动作用语统一为“Force sign out”。
- 文案覆盖在线用户操作、二次确认、自身操作提醒、进行中及结果反馈、角色权限名称和说明、操作历史事件标签及筛选项。界面上的已有相关记录通过统一显示标签采用新用语。
- 个人菜单的主动退出与全设备强制退出是不同动作，前者继续使用“退出登录”。
- 保持既有强制退出含义：撤销目标的所有现有登录资格，可以针对有权限者自己或超级管理员，目标可以重新登录。确认、取消、重复提交保护及失败重试继续可用。
- 导航结构由现有后台外壳统一提供。一级菜单按首页、用户与权限、系统监控、系统设置组织，实际显示取决于权限。
- “系统监控 / System monitoring”使用与现有分组一致的可展开导航交互，下面依次为在线用户、操作历史，作为分组入口使用。
- 在线用户从用户与权限分组移出，操作历史由独立一级入口移入系统监控。用户与权限分组保留用户、邀请、角色。
- 继续按各页面原有查看权限控制子菜单；至少存在一个可见子菜单时才显示父分组。菜单归组不会赋予额外查看或操作权限。
- 当前子页面应具有正确的导航选中状态，其父分组在进入该页面时可见、可定位。系统设置保持最后。
- 既有页面路由、收藏链接和直接访问的授权检查沿用原有行为。
- 全后台采用一个页面主标题的规范；说明性页面副标题和重复表达页面主题的卡片标题应删除。重复的语义标题也应清理，不能只按字符串完全相同判断。
- 核查范围覆盖首页、用户、邀请、角色、在线用户、操作历史、系统设置及后台共用的认证页面标题容器。已有合规页面无需为满足范围而产生无意义改动。
- 页面主标题与实际内容分区、确认框、状态反馈的标题应按含义区分。规范清理页面级装饰性说明和主题重复，不把独立内容分区或完成任务所需的正文误判为重复标题。
- 删除标题或说明后整理相应容器与间距，使操作区、筛选区和表格自然衔接。
- 中英文资源、导航和页面组件共同落实这些规则；已有项目代理规范和领域词汇是长期约束。
- 本次调整集中在后台显示与导航组织，不需要新增业务实体、数据库迁移或新的 API 契约。

## Testing Decisions

- 主要验收入口沿用现有真实浏览器 E2E，继续满足用户此前明确要求的真实浏览器验证。复用现有认证及在线用户流程，以页面可见结果验证此次变更。
- 好的测试验证用户能看到什么、能进入哪里、能执行什么，以及交互后的结果；不以翻译键存在、组件内部状态、函数调用次数或特定样式类名作为验收替代。
- 导航验收覆盖同时拥有两项查看权限、只拥有其中一项、两项都没有的账户，验证父子分组、顺序、入口数量、选中状态和直接访问控制。
- 文案验收覆盖中英文在线页面、普通目标与自己作为目标的确认框、操作反馈、权限配置和操作历史中的相应标签。
- 复用真实强制退出流程验证新文案下的确认、取消、目标多设备退出及重新登录；不通过 mock 认证或撤销结果代替真实流程。
- 标题验收逐页检查范围内的页面，每页只有一个页面主标题，并且没有说明性页面副标题和重复主题标题。在线用户既有测试中只选第一个同名标题的方式应改为能发现重复的断言。
- 标题检查同时核对语义上重复但文字不同的标题，例如页面主题与紧接其后的同主题列表卡片标题；保留实际内容分区的正常标题层级。
- 在桌面及窄视口查看菜单、标题、筛选区和操作区，确认删除文字后的间距、换行与键盘操作正常。
- 优先扩展现有浏览器测试；已有认证页面单标题测试、导航测试、在线用户权限/确认测试可作为先例。只在有必要快速定位交互问题时补充现有组件测试，不为纯展示调整建立新的后端测试入口。
- 运行相关前端测试、类型检查和生产构建；模板文件或资源清单发生变化时执行生成器与打包完整性检查。
- 实施阶段在 Centaurus 运行验证，代码在本地修改后单向同步，使用隔离验收账号和数据，并转发所需服务端口。交付时单独报告真实浏览器结果。

## Out of Scope

- 重新设计在线判定、会话失效检测、权限体系、全设备撤销机制或审计存储。
- 改变强制退出的目标范围、重新登录能力，或者把它变为禁用账户。
- 新增监控仪表盘、指标图表、告警、设备详情或 IP 展示。
- 改变菜单分组所对应的页面权限，或者因为归组而授予额外权限。
- 全面重做后台视觉主题、配色、字体或组件库。
- 删除表单帮助、业务内容、错误说明、确认影响等完成操作所需的信息。
- 将历史需求文档中的口语表达批量改写，或为显示文案变更迁移既有业务数据。
- 在规格整理阶段直接实施、提交代码或更新应用服务。
