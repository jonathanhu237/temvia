# 系统邮件配置、首页运行提醒与统一 RBAC 权限组合

Status: resolved
Labels: ready-for-agent

## Problem Statement

管理员目前需要逐次选择邀请邮件语言，密码重置及密码修改通知又跟随操作页面语言，导致同一个内部系统的邮件语言不一致。SMTP 配置依赖部署环境变量，管理员无法在后台配置或验证邮件服务；系统也缺少明确的“邮件尚未配置”状态和引导。

现有权限混用 read/manage 命名及 Super Admin 专属操作。邀请权限隐式依赖用户读取等其他权限，增加了理解成本；另一方面，完全取消组合约束又可能产生“授予了邀请写权限，却无法选择角色并完成邀请”的配置。作为长期复用模板，系统需要统一、可解释的权限模型，以及防止越权授予和共享角色误操作的边界。

## Solution

提供独立的系统设置页面，内部使用邮件配置 Card，集中配置 SMTP、发件人和默认邮件语言。首次配置语言无预选，必须主动选择；显式保存后跨设备生效。提供使用当前未保存表单的测试邮件功能，允许先验证再保存。首页集中展示运行提醒，本轮只实现邮件未配置提醒。

邀请邮件、密码重置邮件和密码修改成功通知统一使用系统默认邮件语言。个人界面语言继续保持浏览器偏好，不随系统配置改变；邀请时不再逐次选择邮件语言。缺少正式邮件配置时，相关发送操作明确提示联系管理员，不阻止初始化和登录。

RBAC 统一采用独立的 resource.read / resource.write 权限。角色编辑器提供“无权限／只读／读写”，通过明确的功能权限组合补齐后台操作所需权限，保存实际权限集合。读写组合显式包含两项，运行时不从 write 推导 read。角色管理及用户角色分配可委派，但操作者不能授予自己未拥有的权限，也不能修改或删除超出自身权限范围的角色。本轮不引入 Casbin。

## User Stories

1. 作为系统管理员，我希望有独立的系统设置页面，以便集中管理跨设备生效的配置。
2. 作为系统管理员，我希望邮件配置在一个 Card 内完成，以便不必在多个分类页面之间跳转。
3. 作为系统管理员，我希望未来配置可以增加其他 Card，以便沿用相同的设置入口。
4. 作为首次配置邮件的管理员，我希望语言没有预选项，以便明确决定系统邮件使用的语言。
5. 作为系统管理员，我希望邀请、密码重置和密码修改通知统一使用默认邮件语言，以便收件人获得一致的邮件体验。
6. 作为邀请管理员，我希望邀请表单不再要求选择邮件语言，以便减少重复操作。
7. 作为管理员，我希望个人界面语言独立于邮件语言，以便调整自己的浏览器偏好而不影响系统。
8. 作为邀请管理员，我希望人工重发或续期使用最新系统语言，以便已有邀请也能采用新的配置。
9. 作为邮件收件人，我希望同一个邮件任务的自动重试保持原语言，以便发送失败不会改变邮件内容语言。
10. 作为系统管理员，我希望在后台填写 SMTP 主机和端口，以便无需修改部署环境变量。
11. 作为系统管理员，我希望选择 SMTP 加密方式，以便适配邮件服务器要求。
12. 作为系统管理员，我希望认证可以关闭，以便使用无需用户名密码的邮件中继。
13. 作为系统管理员，我希望配置发件人邮箱和名称，以便收件人识别系统邮件。
14. 作为系统管理员，我希望 SMTP 密码加密保存在数据库中，以便不以明文持久化凭据。
15. 作为系统设置查看者，我希望只能看到密码是否已设置，以便读取配置不会暴露原密码。
16. 作为系统管理员，我希望明确替换或清除密码，留空保留原值，以便不会误删已有凭据。
17. 作为系统管理员，我希望技术参数有合理默认值，以便不必理解连接超时等细节才能完成配置。
18. 作为系统管理员，我希望点击保存后才生效，以便编辑过程不影响正常发信。
19. 作为系统管理员，我希望切换页面后保留未保存的普通字段，以便继续编辑。
20. 作为系统管理员，我希望密码不写入浏览器持久化草稿，以便减少凭据暴露。
21. 作为同时编辑设置的管理员，我希望旧版本保存被拒绝并保留草稿，以便不会覆盖他人的更新。
22. 作为系统管理员，我希望用当前未保存的 SMTP 配置发送测试邮件，以便先验证再切换正式配置。
23. 作为系统管理员，我希望测试邮件默认发送给自己，以便方便确认结果。
24. 作为系统管理员，我希望测试不会改变正式配置，以便测试新服务器时正常邮件仍使用原服务器。
25. 作为系统管理员，我希望保存不强制要求测试成功，以便配置流程不依赖当时邮件服务的可达性。
26. 作为系统管理员，我希望保存后无需重启即可使用新配置，以便正常管理系统。
27. 作为首次初始化的管理员，我希望不配置邮件也能创建账号和登录，以便先进入后台完成设置。
28. 作为有设置查看权限的用户，我希望首页提示邮件尚未配置，以便知道该问题需要处理。
29. 作为有设置写权限的用户，我希望提醒能引导我前往配置，以便及时解决问题。
30. 作为用户，我希望配置完成后提醒自动消失，以便首页只展示当前问题。
31. 作为尝试邀请或重发的管理员，我希望邮件未配置时收到明确提示，以便知道需要联系管理员。
32. 作为申请密码重置的用户，我希望邮件未配置时获知服务不可用，以便不会徒劳等待邮件。
33. 作为角色管理员，我希望所有资源采用一致的读写命名，以便理解权限目录。
34. 作为角色管理员，我希望选择读写时明确保存读和写两项权限，以便知道实际授予了什么。
35. 作为角色管理员，我希望界面补齐并解释邀请功能需要的角色读取权限，以便不会漏配。
36. 作为角色管理员，我希望移除被其他功能需要的权限时获知影响，以便避免保存不可用的组合。
37. 作为邀请管理员，我希望没有用户列表读取权限也能创建邀请，以便不必获得无关数据访问权。
38. 作为邀请管理员，我希望角色选项只允许选择自己有权分配的角色，以便避免越权邀请。
39. 作为被委派的角色管理员，我希望可以管理自身权限范围内的自定义角色，以便减少对 Super Admin 的依赖。
40. 作为被委派的用户管理员，我希望可以给用户分配允许范围内的角色，以便履行职责。
41. 作为系统管理员，我希望角色编辑和分配都不能授予操作者未拥有的权限，以便防止提权。
42. 作为系统管理员，我希望超范围角色不能被普通角色管理员修改或删除，以便保护其他管理职责。
43. 作为角色管理员，我希望保存前知道修改会影响多少用户和邀请，以便理解共享角色的影响。
44. 作为已分配角色的用户，我希望角色修改后权限随之更新，以便系统执行最新授权。
45. 作为系统管理员，我希望内置角色和最后一个超级管理员继续受到保护，以便不会失去系统管理能力。
46. 作为权限受限的用户，我希望菜单、页面和操作与权限一致，以便不遇到明显无效的入口。
47. 作为系统管理员，我希望直接调用 API 也会执行权限及范围校验，以便前端隐藏不成为唯一保护。
48. 作为模板维护者，我希望新增功能优先使用已有资源权限和明确的组合，以便不为每个按钮新增权限。

## Implementation Decisions

### 页面、状态与保存

- 在现有 Dashboard 新增独立系统设置入口和页面，内部只有邮件配置 Card，不增加分类导航或初始化邮件向导。扩展现有首页，不新建重复首页。
- 邮件配置是应用范围的共享配置，持久化在数据库中；包含配置版本、SMTP 连接与认证信息、发件人信息、明确选择的邮件语言及必要更新时间。无有效已保存配置时状态为未配置。
- 首次语言值为空，只支持已有中英文邮件模板对应的语言；保存和测试均要求明确有效语言。不得从管理员界面、浏览器或环境自动填充。再次打开已保存配置显示已保存语言。
- Card 提供主机、端口、加密方式、认证开关、用户名、密码、发件人邮箱、发件人名称和默认邮件语言。沿用已有 SMTP 能力和校验边界，不降低生产环境已有 TLS 约束；无需认证不等于无需 TLS。端口有效、发件地址合法、字段拒绝换行注入，启用认证时必须具有完整有效凭据。
- 连接超时等参数使用现有合理默认值，不增加用户输入。生产部署示例及开发 Mailpit 流程与新配置来源一致；缺少 SMTP 本身不再导致服务无法启动。
- 显式保存完整邮件配置，原子提交，失败不产生部分生效。请求携带读取时的配置版本；首次创建也防止并发覆盖。版本冲突沿用标准冲突响应，保留草稿，由用户主动加载最新配置，不自动覆盖或无限重试。
- 普通字段沿用现有 Zustand 表单草稿生命周期，草稿按登录主体隔离，退出登录清理。密码仅限受控的短期内存编辑，不进入 localStorage、sessionStorage、持久化查询缓存或日志；保存、退出及草稿丢弃时清理。
- UI 使用现有中英文文案和问题响应方式。配置保存、测试、缺少权限与版本冲突分别反馈，不用笼统成功消息掩盖失败。

### SMTP 凭据与测试

- SMTP 密码必须采用服务端可解密的认证加密存储，使用成熟密码学原语及部署提供的独立密钥；不能仅哈希，因为投递时需要使用原始凭据。加密密钥不与密文共同存入配置表，不复用登录或邀请签名密钥。
- 读取配置只返回密码已设置状态，不返回原密码或密文。保存契约明确区分保留、替换、清除，空输入默认保留；清除与启用认证的组合必须通过凭据完整性校验。
- 测试默认发送给当前登录管理员的已知邮箱，本轮不扩展任意收件人发送器。测试使用当前表单中的 SMTP、发件人及语言；如果选择保留已保存密码，由服务端取用，客户端不读取原密码。
- 测试是独立的、有界超时的发送操作，不创建邀请或密码恢复任务，不改变正式配置版本、配置状态或普通邮件队列。使用已保存密码的测试携带关联配置版本，过期时提示刷新，避免混用不同版本凭据。
- 保存无需测试成功，测试成功也不会自动保存。提示测试请求成功不等同于保证最终进入收件箱；错误内容不得泄露密码、完整连接认证信息。
- 缺少加密密钥或解密失败不得回退明文存储或使用旧环境变量凭据。实现阶段在部署文档明确密钥配置和备份要求；邮件功能给出可诊断的受控失败，不将凭据错误暴露给普通用户。

### 邮件行为与 API

- 系统设置读取、版本化保存、测试邮件及首页运行提醒使用现有认证、授权和标准错误响应设施。精确路由命名沿用项目约定，不引入独立外部服务。
- 邀请、密码重置请求和密码修改成功通知的语言由服务端读取已保存的默认邮件语言决定。移除现有相关请求中的客户端邮件语言选择，不能让旧输入覆盖系统配置；必要的界面 locale 仍只用于界面反馈。
- 创建邮件任务时固定 locale。自动重试保留任务 locale；人工重发或续期建立新任务，使用当时最新系统语言，继续执行既有旧令牌／任务失效规则。
- 每次开始正式投递或重试使用最新已提交 SMTP 和发件人配置的一致快照，无需重启；已开始的发送使用其启动时快照完成。不得改变处理中任务的 locale。
- 人工重发确认不再声称沿用原邀请语言，也不要求邀请管理员取得 settings.read。确认文案可以说明采用系统默认邮件语言，不读取受保护的完整设置来展示语言。
- 未配置时，创建邀请、人工重发／续期、申请密码重置返回可识别的邮件不可用问题，中文为“邮件服务尚未配置，联系管理员。”，提供英文等价文案。拒绝操作不得新建邀请、使旧令牌失效或留下不可发送任务。
- 区分未配置与已配置但暂时不可达：后者沿用既有队列重试、租约、过期及终止机制，不因 SMTP 暂时宕机把配置标为未配置。
- 密码重置的公开入口在未配置时对任意邮箱保持相同响应，不泄露账号存在性；已配置时保留既有防枚举和限流行为。已有有效邀请接受和密码重置完成继续遵守原令牌规则，不能因临时 SMTP 故障撤销已成功的密码修改。
- 本轮无邮件配置删除／重置入口，因此正常流程中有效密码重置令牌产生于已完成邮件配置之后；异常配置失效不得导致悄悄使用默认邮件语言。

### 首页运行提醒

- 首轮仅提供“邮件服务尚未配置”的当前状态提醒，使用现有首页区域承载，不建设通知历史或通用监控系统。
- settings.read 控制提醒及设置读取的可见性；settings.write 控制配置动作，具备完整设置读写组合者显示前往配置入口。无设置权限者不获得配置内容，可在尝试邮件操作时收到联系管理员提示。
- 保存有效配置后更新首页状态并移除提醒。提醒依据是否有完整正式配置，不依据是否测试成功或是否完成实时 SMTP 健康检查。测试未保存时提醒不消失。

### 独立权限与功能组合

- 继续使用自有集中授权逻辑，不引入 Casbin、外部策略服务或新的授权框架。
- 权限目录统一为 users.read/write、roles.read/write、invitations.read/write、settings.read/write。invitations.manage 由 invitations.write 替换；Super Admin 保留内置身份并自动具有目录中的全部权限。
- 底层读与写独立；有效权限来自用户当前角色的实际权限并集，不按 write 推导 read，不在鉴权时递归补权。
- 角色配置按资源提供无权限／只读／读写，读写显式保存两项。功能权限组合是配置所需权限的声明，不是另一套角色继承或新的权限标识。新增功能优先复用资源权限，不因一个按钮新增一个权限。
- 组合基础如下，后端验证每个保存的角色可以提供所选完整能力，不依赖另一个角色补足残缺组合：

| 配置能力 | 明确包含的权限 |
| --- | --- |
| 任一资源只读 | 对应 resource.read |
| 任一资源读写 | 对应 resource.read 和 resource.write |
| 邀请读写 | invitations.read、invitations.write、roles.read |
| 用户角色分配界面 | users.read、users.write、roles.read |
| 角色读写 | roles.read、roles.write |
| 系统设置读写 | settings.read、settings.write |

- 用户角色分配界面加入 roles.read 是与邀请选择角色相同规则的一致性落实。邀请组合不包含 users.read；邀请列表读取也不再依赖 users.read。
- UI 自动选中并明确标注组合需要的权限；移除依赖时解释受影响能力并要求同步调整，不能静默清除其他业务权限。保存提交可见的完整集合，服务端拒绝缺项和未知项，不能悄悄补上操作者没看到的权限。
- 组合补齐后的全部权限仍必须处于操作者授权范围。前端不能提供操作者无权授予的完整组合，后端不能因自动补齐绕过范围校验。
- 原子接口按实际动作检查权限；跨资源功能在读取关联资源时检查其 read。创建邀请并分配角色显式检查 invitations.write 和 roles.read；完整邀请页面还需要 invitations.read。撤销、重发保留邀请写权限及目标角色授权上限检查，不因为服务端内部查询角色而自动开放角色数据。
- 组合目录由服务端权威定义，前端消费相同元数据；不在前后端分别维护会漂移的依赖图。未知组合或不完整定义应在验证中暴露，不能静默扩大权限。

### 委派与角色生命周期

- 角色创建／修改／删除检查 roles.write，用户角色分配检查 users.write，替换现有仅检查 Super Admin 的普通管理入口；查询和关联角色选择仍分别检查读权限。
- 授权上限以操作提交时操作者当前有效权限为准。创建／编辑角色后的权限集合，以及分配／邀请中的目标角色权限，必须是操作者权限的子集，允许相等。
- 非 Super Admin 不能修改或删除修改前即包含超范围权限的角色；删除仍要求无任何用户或邀请关联。不能仅校验编辑后的集合，借先移除权限绕过保护。
- 角色分配变更对本次新增和移除的角色执行范围校验，不得借整份列表替换移除超范围关联。无关且未变动的关联保持原样；仅 Super Admin 可授予或移除 Super Admin 身份。
- 内置角色不能编辑／删除；最后一个可用 Super Admin 保护保持。角色分配数量继续同时包含已激活用户和未接受邀请，过期邀请仍占用角色，直到关联按生命周期移除。
- 角色编辑保存前提示将影响的用户及邀请数量，不增加角色页人员明细表。保存后共享角色权限变更直接作用于所有关联用户；邀请激活时沿用其关联角色的最新权限。
- 保留角色和分配版本锁，并在实际事务提交边界保证授权范围、关联及最后管理员检查的一致性，避免检查后并发修改造成越权。不能仅使用浏览器缓存的权限判断。
- 前端按 API 当前有效权限控制导航、直接路由和操作；无权内容不先获取后隐藏。相关变更、重新聚焦或收到权限拒绝时刷新主体权限和相关缓存；后端始终以当前授权拒绝被撤销能力，不能等待浏览器重新登录。

### 数据与兼容范围

- 新增共享邮件配置的持久化和版本契约，调整邮件发送配置来源、服务启动装配、权限目录及角色编辑元数据。
- 当前尚未上线，不提供旧 SMTP 环境变量导入、旧权限名称长期别名或邮件语言旧契约过渡期；仍需正常维护数据库结构迁移、开发种子及测试夹具，使现有开发环境能明确迁移或按既有流程重建，不能无说明丢弃数据。
- 原有邀请、重置安全机制、Cookie／会话、CSRF、输入校验和限流继续适用。新增设置写入和测试入口复用相同保护。

## Testing Decisions

- 好的测试以外部行为为依据：可访问的数据、允许或拒绝的操作、最终保存结果、邮件内容及实际配置切换。避免验证内部辅助函数调用次数、组件结构或逐字复制实现。
- 优先以现有 Playwright 浏览器流程贯穿配置、首页提醒、邀请和真实邮件捕获；复用现有 Mailpit 集成，不向真实外部收件人发送测试邮件。
- 既有 API HTTP 权限矩阵覆盖无权限、只读、读写、Super Admin、不同自定义角色和越权提交。加入未配置服务、缺少角色读取、未知／不完整权限组合、角色范围及凭据不回显场景；测试不能只验证隐藏按钮。
- 复用 PostgreSQL 集成测试验证配置原子保存、两个管理员的版本冲突、角色变更和分配的并发授权边界、最后管理员及关联删除约束。不同操作者各自持有角色版本时，陈旧权限不能绕过提交时检查。
- 复用现有邮件 dispatcher、SMTP adapter 和密码恢复测试入口验证：三类邮件采用系统语言；自动重试保留任务语言；人工重发采用最新语言；SMTP A/B 切换在下一次投递生效；未保存测试使用 B 而正式邮件仍使用 A；临时投递失败不使业务回滚。
- 若真实邮件端到端环境不能稳定制造重试或发送中切换，在已有应用邮件发送接口使用可控测试替身；不为测试新增生产接口或独立测试框架。
- 浏览器重点覆盖首次语言空选、测试后仍未保存、保存失败保留草稿、普通字段导航恢复、密码不持久化、只读设置、组合联动及依赖移除解释。中英文、键盘操作、现有无障碍和弹出控件滚动条回归沿用现有测试设施。
- 测试底层拥有 write 不会自动通过 read 检查；配置界面选择读写后实际持久化两项。验证无 users.read 的完整邀请角色可以邀请，却不能读取用户列表。
- 配置加密验证以持久化不可见明文、正确凭据可用、密文篡改或密钥错误失败、读 API／错误／日志不泄露凭据为边界，不断言特定随机密文。
- SMTP 校验测试覆盖可选认证、保留／替换／清除、超时和现有生产 TLS 约束；公开密码恢复在邮件未配置时对存在和不存在邮箱响应一致。
- 现有先例包括浏览器认证与 Mailpit 流程、访问管理组件测试、API 访问权限矩阵、PostgreSQL 并发集成测试及邮件投递器测试。按风险补足现有边界，不在每层重复所有案例。
- 测试执行遵循 Centaurus 工作流：本地编辑，单向同步后运行，转发需要的服务端口。本次规格编写只做文档检查，不启动应用或执行测试。
- 用户已确认上述测试边界：浏览器端到端流程、API／数据库越权及并发测试，以及现有邮件投递测试。

## Out of Scope

- 本轮文档交付不实现应用功能，不创建提交、部署或发送真实邮件。
- Casbin、OpenFGA 等第三方授权引擎；多租户、角色继承、独立可授予权限边界、审批流及 escalate/bind 例外。
- 为每个按钮增加独立权限、任意用户直接权限配置以及新的角色页人员清单。
- 用户个人邮件语言、按收件人自动探测语言、单次邀请覆盖语言、多语言同封邮件或新增模板语言。
- 初始化邮件向导、旧 SMTP 环境变量自动导入和未上线产品的兼容过渡层。
- 通用运行监控、SMTP 周期健康检查、提醒历史、邮件投递分析仪表盘。
- 邮件配置删除入口、任意收件人的邮件发送工具、用户可编辑连接超时等高级 SMTP 参数。
- 密码修改设置页面等未来系统设置；当前只预留统一页面结构。
