# 在线用户管理

Status: resolved
Triage: ready-for-agent
Testing seams: confirmed-http-integration-and-browser-e2e
Implementation authorization: explicitly-authorized-2026-09-09

## Problem Statement

后台管理员无法集中判断哪些用户仍处于登录状态，也无法主动终止指定用户在各个设备上的现有登录。仅知道谁最近操作过页面，会漏掉暂时没有活动、关闭了网页但仍持有有效登录会话的用户。

管理员需要可靠地查看在线用户，并在需要时让指定用户退出所有设备。该操作应有明确的权限和确认提示，结果可以追溯，被踢用户也应理解为何返回登录页。

## Solution

在“用户与权限”下提供“在线用户”页面。在线用户指至少持有一个有效登录会话的用户，无须最近五分钟有活动，关闭网页本身也不会让有效会话失效。

页面按用户聚合，展示姓名、邮箱、有效会话数和最近活动时间，支持姓名/邮箱搜索与自动刷新。拥有查看权限的人可以查看列表；拥有踢下线权限的人可以将任意用户的所有现有登录会话撤销，包括超级管理员和自己。只读人员不能踢人，超级管理员默认拥有查看和踢下线两项权限。

踢人前二次确认。踢自己时明确告知当前页面也将退出。操作成功后，旧登录会话立即失效，正常运行并可联网的页面约三十秒内提示“登录已失效，请重新登录”并跳转登录页。用户可以重新登录，踢下线不等于禁用用户。后台状态检查不能延长登录有效期或空闲过期时间。

成功和失败的踢下线操作都进入现有操作日志，记录操作者、目标用户、时间及结果。

## User Stories

1. 作为拥有查看权限的管理员，我希望在“用户与权限”中找到在线用户页面，以便集中管理当前登录状态。
2. 作为管理员，我希望在线列表包含所有持有有效登录会话的用户，以便不会漏掉暂时没有操作的人。
3. 作为管理员，我希望用户关闭网页但登录仍有效时继续出现在列表中，以便区分关闭页面和退出登录。
4. 作为管理员，我希望五分钟以上没有活动但会话尚未过期的用户仍被列为在线，以便在线判定符合登录有效性。
5. 作为管理员，我希望同一个用户的多个有效登录聚合成一行，以便不会把多个设备误认为多个人。
6. 作为管理员，我希望看到用户姓名和邮箱，以便准确识别操作对象。
7. 作为管理员，我希望看到每个用户的有效会话数，以便了解其当前有多少个登录仍然有效。
8. 作为管理员，我希望看到最近活动时间，以便判断用户最近是否使用过系统。
9. 作为管理员，我希望过期、退出或已撤销的会话不计入有效会话数，以便列表反映真实的访问资格。
10. 作为管理员，我希望用户最后一个有效会话失效后从列表消失，以便不会把已退出的人视为在线。
11. 作为管理员，我希望按姓名或邮箱搜索在线用户，以便快速定位要查看或踢出的对象。
12. 作为管理员，我希望列表自动更新，以便不必反复重新进入页面。
13. 作为管理员，我希望列表加载失败与没有在线用户有不同的提示，以便不会误把系统故障理解为空列表。
14. 作为权限配置者，我希望分别授予查看在线用户和踢下线的权限，以便让需要查看的人不必获得踢人能力。
15. 作为只读人员，我希望可以查看在线信息但不能执行踢下线，以便权限边界清晰。
16. 作为没有查看权限的用户，我希望在线用户入口和数据受到访问控制，以便其他用户的信息不会被无权访问的人读取。
17. 作为超级管理员，我希望默认拥有查看和踢下线能力，以便无需额外配置就能管理登录状态。
18. 作为拥有踢下线权限的管理员，我希望能够踢任何目标用户，包括超级管理员，以便权限不会再被角色层级规则隐式限制。
19. 作为拥有踢下线权限的管理员，我希望能够踢自己，以便终止自己在其他设备上的所有现有登录。
20. 作为管理员，我希望踢人前确认目标及“退出所有设备”的影响，以便避免误操作。
21. 作为管理员，我希望取消确认后不发生任何踢下线操作，以便安全地放弃操作。
22. 作为管理员，我希望踢自己时看到当前页面也会退出的提示，以便提前理解操作结果。
23. 作为管理员，我希望一次踢下线终止目标用户所有现有会话，包括闲置设备上的会话，以便不需要逐个查找设备。
24. 作为管理员，我希望操作执行期间避免重复提交，并在成功或失败后得到明确反馈，以便知道操作是否完成。
25. 作为管理员，我希望操作失败时能够保留目标并重试，以便处理暂时的网络或服务故障。
26. 作为被踢用户，我希望旧登录在操作成功后立即无法访问受保护资源，以便退出行为在所有设备上都有效。
27. 作为被踢用户，我希望即使停留在页面没有操作，也能约三十秒内看到登录失效提示并返回登录页，以便知道需要重新登录。
28. 作为被踢用户，我希望能够重新登录，以便踢下线不会被误用为永久禁止访问。
29. 作为登录用户，我希望自动状态检查不会持续刷新登录有效期或空闲时间，以便系统保留既有过期规则。
30. 作为登录用户，我希望暂时断网不会被当成明确的登录失效，以便服务恢复后可以继续使用尚有效的会话。
31. 作为有权查看操作日志的人员，我希望看到成功和失败的踢下线记录，以便追溯谁在何时对谁执行了什么操作。
32. 作为中英文界面的使用者，我希望页面、确认框、操作反馈和失效提示使用当前界面语言，以便与现有后台体验保持一致。

## Implementation Decisions

- 以领域词汇 Online user、Force sign-out 和 Force sign-out permission 为准。在线状态取决于有效登录会话，不使用“最近五分钟活跃”作为过滤条件。
- 有效性沿用现有认证规则：会话存在、没有空闲过期或绝对过期，并且仍被当前账户认证版本认可。已撤销、已退出、过期及无对应账户的会话不能让用户保持在线。
- 按用户聚合所有有效会话。有效会话数与在线判定采用同一套有效性规则；最近活动时间从有效会话的实际活动记录计算。纯状态检查不能把自己产生的请求伪装成用户最近活动。
- 延续现有认证应用层、PostgreSQL 账户存储、Redis 会话存储与 HTTP 适配器的职责划分，不引入第二套独立的在线身份或撤销规则。
- 沿用账户认证版本作为所有设备撤销的权威机制。操作提交成功后，携带旧版本的会话在之后的受保护请求中必须被拒绝；缓存清理不是撤销正确性的前提。操作不能回滚已经执行完毕的业务请求。
- 撤销只针对已有登录资格，不禁用账户。撤销之后完成的新登录可以获得新会话；并发登录不能让旧版本会话绕过撤销。
- 权限沿用资源的读写模型，分别使用 online-users.read 和 online-users.write。写权限不隐式赋予读取在线列表的能力。通过页面管理需要相应查看与操作能力，后端必须验证操作权限。
- 超级管理员默认拥有两项权限。目标是否为超级管理员、目标角色是否超出操作者角色范围、目标是否为操作者本人，都不构成额外的踢下线限制。
- 接口在执行时以操作者当前权限为准，不能仅依赖前端按钮可见性或旧的页面权限快照。修改请求沿用现有同源校验与统一问题响应格式。
- 复用当前已有的在线用户查询和逐人踢下线接口形状：查询返回用户集合，每项包含用户标识、姓名、邮箱、最近活动时间及有效会话数；逐人踢下线根据目标用户标识执行，成功返回无内容响应。业务有效性必须按本规格修正，不能因为接口已存在就保留错误的判定。
- 查询结果、确认框和日志不暴露会话凭证。页面不展示 IP、设备详情或会话内部标识。
- 会话监控需要能够检查有效性但不更新最近活动时间、空闲过期时间或绝对过期时间。现有认证查询路径会续期，因此不能直接作为本功能的周期性状态检查。
- 自动刷新在线列表时，也不能因为认证这次后台请求而让操作者的空闲会话一直续期。普通业务请求的既有认证与续期行为不在本次调整范围内。
- 被踢后旧会话立即不可用。已打开页面以约三十秒的检测目标处理登录失效，先提供本地化提示再返回登录页，并清理不再应保留的账户相关缓存。
- 仅明确的未认证结果触发登录失效处理。网络错误或依赖服务暂时不可用不能等同于被踢或退出成功。浏览器被系统挂起、离线时无法保证墙上时钟三十秒的跳转，恢复执行和联网后应尽快重新检查。
- 页面复用现有后台导航、表格、确认框、查询状态、反馈组件和中英文资源。搜索匹配姓名或邮箱，列表支持自动刷新；具体刷新间隔属于实现细节，不改变在线定义。
- 一次确认针对一个用户，影响其所有现有设备。请求处理中避免重复提交；取消不发送撤销请求；成功后更新列表；失败提供错误反馈和重试机会。
- 踢自己仍走同样的权限与确认流程，额外明确当前页面会退出，并正确进入登录失效处理。
- 复用现有操作日志能力记录踢下线成功或失败。记录操作者、目标用户、发生时间和结果；无法确认的操作者按既有未验证行为记录规则处理，不伪造身份。
- 第一版不要求新增持久化业务实体或重构角色体系。是否需要内部索引等属于后续实现选择，不能改变上述行为或让历史有效会话在升级后漏出列表。

## Testing Decisions

用户已明确要求加入真实浏览器端到端验收。测试方案由现有 HTTP 集成入口和真实浏览器用户流程组成；保留少量组件测试用于快速定位交互问题。

- 好的测试验证用户可观察的行为：谁出现在列表、谁能执行操作、旧会话能否访问资源、是否按原计划过期、页面如何反馈及日志记录了什么。避免断言内部函数调用次数、Lua 文本、SQL 字符串、缓存键名或组件内部状态。
- 以现有 HTTP handler 为主要业务验收入口，使用真实认证应用服务连接隔离的 PostgreSQL 和 Redis。通过登录取得多个会话，再调用在线列表、踢下线和受保护接口，以较高的单一入口覆盖业务链路，避免仅由 fake 返回预期结果就判定撤销成功。
- 沿用现有 HTTP 认证、权限矩阵、同源保护和审计测试的组织方式，以及已有隔离 PostgreSQL/Redis 的集成测试基础。前端复用确认框与会话监控的组件测试基础。
- 在线列表验收：有效但超过五分钟未活动的会话仍在线；多会话按人聚合；不同会话的最近活动正确；一个会话退出后仍有其他有效会话则继续在线；最后一个会话失效则消失；已撤销和已删除账户的残留会话不计数。
- 权限验收：匿名、无权限、只读、有操作权限及超级管理员；无查看权限不能获取列表，无操作权限不能踢人；有踢下线权限的非超级管理员可以踢超级管理员；允许有权限者踢自己。目标角色层级不是拒绝理由。
- 撤销验收：同一用户至少两个独立会话，操作成功后均被受保护接口拒绝；另一用户的会话不受影响；被踢用户可以重新登录。覆盖缓存保留旧会话记录和并发登录场景，证明旧会话不会重新获得效力。
- 不续期验收：配置短的空闲/绝对过期时间，在原本会过期的时间段内重复执行后台状态检查和在线列表自动刷新，确认会话仍按原规则过期。通过之后的认证结果验证，不以 TTL 字段实现细节为唯一证据；同时验证被观察目标的会话不会因为管理员查询而续期。
- 失败验收：依赖不可用、权限被拒绝、目标不可用、错误 Origin 时不能报告踢出成功或泄露在线列表。数据库撤销未完成时不可声称所有设备已退出。
- 日志验收：成功及失败踢人记录可经现有操作历史读取，操作者、目标、时间和结果正确，且不包含会话凭证。
- 前端组件测试补充以下交互行为，不能替代真实浏览器端到端验收：搜索和聚合信息展示、只读动作限制、二次确认、取消无操作、踢自己提示、防重复提交、成功刷新、失败可重试、空列表与错误态区分、中英文文案。
- 会话监控组件使用可控时间验证约三十秒内的失效提示和登录跳转，以及账户缓存清理；网络暂时不可用时不误退出。后台检查不续期的保证由真实会话集成验收覆盖。
- 真实浏览器验收复用现有端到端测试基础，运行生产构建或与交付一致的应用，连接隔离的真实 API、PostgreSQL 和 Redis，不 mock 认证、会话状态或撤销接口。测试账号与角色可以通过隔离测试夹具准备；核心登录、查看列表、确认踢人及页面跳转经真实 UI 完成。
- 多设备端到端流程：普通管理员拥有查看与踢下线权限；同一个目标超级管理员分别在两个独立浏览器上下文登录。操作者在在线用户页面确认目标聚合信息并踢出，两个目标上下文均在正常联网运行条件下约三十秒内出现失效提示并进入登录页；操作者保持登录。此流程同时验证不存在超级管理员目标保护。
- 重新登录端到端流程：被踢用户通过登录页面重新登录，能够正常访问后台，并重新进入在线列表。
- 踢自己端到端流程：用户拥有踢下线权限，在两个独立上下文登录；先取消一次确认，验证仍保持登录且没有成功踢出记录，再确认踢自己，验证明确的当前页面退出提示和两个上下文的最终登录页状态。
- 权限与页面端到端流程：只读用户可以查看列表但无可用踢人动作；无查看权限的用户不能通过入口或直接访问页面读取在线数据；姓名/邮箱搜索能定位目标。覆盖中文确认/失效文案与英文关键流程，不只检查翻译资源存在。
- 状态检查端到端流程：在隔离环境设置可测试的短空闲过期时间，让页面持续打开并自动检查，确认没有真实业务活动时仍按原规则过期；覆盖在线列表停留场景，防止其自动刷新把操作者永久续期。
- 真实浏览器验证以页面可见反馈、导航结果、后续访问资格和日志读取结果为断言；不以组件 mock、手工注入失效状态或直接修改浏览器缓存代替真实被踢过程。约三十秒目标使用合理的测试调度容差，不将离线或操作系统挂起视为服务端撤销延迟。
- 不为每一层重复建立同一套行为测试。仅当 HTTP 集成入口无法稳定控制必要的时间或并发条件时，才在已有应用服务/适配器边界补充精确测试。
- 真实浏览器验收必须在交付报告中单独列出结果，不能以组件测试通过代替；若环境阻塞，必须明确记录未完成的验收项。
- 实现阶段在 Centaurus 运行相关验证，本地仓库为源码唯一来源；使用隔离测试数据，不对开发用户执行试验性踢下线。类型检查、生产构建和生成器模板完整性检查属于交付检查。

## Out of Scope

- 禁用用户、封禁账户或限制被踢用户重新登录。
- 单独踢某个设备或某一个会话。
- 设备详情、IP 展示、地理位置或登录风险分析。
- 批量踢人、全站强制退出。
- 基于角色层级保护超级管理员不被有权限者踢出。
- 把在线重新定义成网页当前打开、实时连接存在或最近几分钟活跃。
- 调整普通业务请求既有的会话续期策略或重新设计全站认证体系。
- 独立的登录历史页面、另建审计系统或对用户发送邮件通知。
- 本次规格整理直接实施、提交代码、更新应用服务。
