# 系统名称与系统图标

Status: resolved
Triage: ready-for-agent

## Problem Statement

管理员无法在系统设置中统一配置系统名称和系统图标。现有浏览器初始标题为 Administration，系统邮件中的名称存在硬编码，导致部署后的产品身份无法通过配置统一。系统需要同时满足默认名称和可选英文名称的展示需求。

## Solution

在系统设置中增加系统名称、可选英文名称和系统图标配置，应用于整个部署。名称覆盖后台、登录、邀请激活、找回密码等页面、浏览器标签标题及系统邮件。中文使用系统名称，英文优先使用英文名称，未填写时回退到系统名称。

管理员上传一张图片，统一用作页面品牌标识和浏览器 favicon；支持预览与恢复默认。名称与图标共同保存后生效，沿用系统设置权限，并记录操作历史。

## User Stories

1. 作为管理员，我希望在系统设置中配置系统名称，以便所有用户看到本部署的名称。
2. 作为管理员，我希望新部署默认使用 Temvia，以便未配置时仍有明确的系统名称。
3. 作为管理员，我希望可选填写英文名称，以便英文使用者看到合适的名称。
4. 作为中文界面用户，我希望始终看到系统名称，以便获得一致的产品身份。
5. 作为英文界面用户，我希望优先看到英文名称，以便理解正在使用的系统。
6. 作为英文界面用户，我希望未配置英文名称时回退到系统名称，以便名称不会为空。
7. 作为管理员，我希望名称自动去除首尾空格，以便避免无意输入的空白。
8. 作为管理员，我希望收到必填和长度校验反馈，以便修正无效名称。
9. 作为管理员，我希望英文名称允许空格、数字和标点，以便使用实际品牌名称。
10. 作为后台用户，我希望后台品牌区域显示配置的名称和图标，以便辨认系统。
11. 作为未登录访客，我希望登录页面显示系统名称和图标，以便确认访问的是目标系统。
12. 作为受邀用户，我希望激活页面显示一致的系统身份，以便确认邀请来源。
13. 作为找回密码的用户，我希望恢复流程显示一致的系统身份，以便辨认正在恢复哪个系统的账户。
14. 作为浏览器用户，我希望标签标题和 favicon 反映系统身份，以便区分多个标签。
15. 作为邮件接收者，我希望邀请、密码重置、密码修改通知和测试邮件使用配置的名称，以便辨认来源。
16. 作为邮件接收者，我希望邮件名称随邮件语言选择并正确回退，以便邮件内容保持一致。
17. 作为邮件管理员，我希望发件人名称保持独立配置，以便更改系统名称不会覆盖邮件设置。
18. 作为管理员，我希望上传 PNG、JPEG 或 WebP 图标，以便使用已有品牌素材。
19. 作为管理员，我希望在保存前预览图标，以便确认选择正确。
20. 作为管理员，我希望非正方形图标等比例居中显示，以便图片不被裁切或拉伸。
21. 作为管理员，我希望图标可以恢复默认，以便撤销自定义图标。
22. 作为管理员，我希望名称和图标一次保存共同生效，以便避免展示半套配置。
23. 作为管理员，我希望保存后当前页面立即更新，以便确认修改成功。
24. 作为其他用户，我希望刷新页面后看到最新配置，以便获得管理员发布的系统身份。
25. 作为只有读取权限的管理员，我希望能查看但不能修改配置，以便遵守职责范围。
26. 作为具有系统设置修改权限的管理员，我希望沿用现有授权编辑，以便无需新增专用角色。
27. 作为同时编辑的管理员，我希望版本冲突时收到重新加载提示，以便不覆盖他人的修改。
28. 作为有操作历史查看权限的管理员，我希望查到配置修改的记录，以便追溯操作。
29. 作为管理员，我希望无效图片或保存失败时原配置仍然有效，以便系统身份保持完整。

## Implementation Decisions

### 已确认的产品规则

- 配置为整个部署共享的系统设置，不属于个人偏好。
- 系统名称默认 Temvia，去除首尾空格后必填，长度为 1–50 个字符；英文名称选填，非空时遵守相同长度限制，不限制为纯英文字母。
- 界面名称依据界面语言选择；邮件名称依据邮件语言选择，两者均在英文名称缺省时回退到系统名称。
- 覆盖面向用户的系统名称，不把代码标识、包名或技术标识当作品牌文案替换。
- 邮件发件人名称继续由现有邮件配置独立管理。
- 同一张系统图标用于页面品牌标识和 favicon；接受 PNG、JPEG、WebP，最大 2 MB。非正方形图片等比例居中，不裁切、不拉伸。
- 图标支持预览与恢复默认，不分别配置深浅色图标。预览与恢复默认属于待保存内容，点击保存后发布。
- 名称与图标共同保存；成功后当前页面立即更新，其他已打开页面刷新后更新，新邮件使用新名称。
- 沿用 settings.read / settings.write 及现有超级管理员规则；write 不隐含 read，设置管理的权限组合保持现有约定。
- 修改写入操作历史；并发编辑不能静默覆盖，后保存者收到重新加载提示。
- 系统设置页面遵守现有单一页面主标题约定，不添加说明性副标题或重复标题。

### 基于现有代码的实现约束

- 扩展现有系统设置、共享 API 客户端和设置页面，复用现有分区导航及反馈方式。
- 在服务端持久化共享配置；复用现有设置版本校验模式，使名称和图标引用作为同一版本发布。存储布局及具体接口路径留给实现阶段确定。
- 登录等未认证页面也需要显示系统身份，因此提供仅包含公开名称及图标信息的读取能力，不暴露邮件配置或其他管理设置；管理读写继续进行权限校验。
- 在公共页面和后台共享名称选择逻辑，并更新浏览器标题及 favicon。图标发布后需要避免旧缓存导致刷新后仍显示旧图标。
- 图片校验由服务端执行，不只依赖文件扩展名或客户端检查；无法解码、类型不支持或超限的文件不得成为已发布图标。
- 复用现有邮件生成及发送流程替换面向用户的系统名称，保留独立的发件人配置，正确转义名称在 HTML 等输出中的特殊字符。
- 复用现有操作历史管道，不记录图片二进制内容。
- 以上技术约束是基于仓库现状的规格整理，不表示已实现；不新增 ADR，当前没有需要单独记录的难以逆转的架构取舍。

## Testing Decisions

- 测试只断言外部可观察行为，不锁定组件内部状态、私有函数、表结构或实现调用顺序。
- 主要入口为现有 Playwright 浏览器端到端测试，参考已有真实服务登录、语言切换、多浏览器会话和权限验收方式；优先通过界面验证完整保存与展示链路。
- 端到端覆盖：默认值、双语名称与英文缺省回退、后台和公开页面、浏览器标题及可加载的 favicon、上传预览、保存后生效、恢复默认、刷新后的持久化，以及只读权限。
- 图标展示包含非正方形素材的视觉验证，确认不拉伸、不裁切；不能仅凭 URL 已变更就认定 favicon 正确。
- 沿用现有设置 HTTP 测试入口补充直接请求的授权、名称边界、图片内容与大小校验、陈旧版本冲突及失败不改变已发布配置。避免为相同规则重复建立多个低层测试入口。
- 沿用现有邮件发送测试，以捕获的出站邮件断言中文、英文、英文缺省回退、主题及正文名称替换、HTML 转义，并确认发件人配置未被覆盖。
- 操作历史通过既有对外读取行为验证配置修改可追溯。
- 测试方案已向用户发起核对；在尚未收到答复时，以上为拟采用方案，不标记为已获确认。

## Out of Scope

- 规格讨论阶段不实施功能；后续用户已通过 implement-loop 明确授权实现，并在 LGTM 后授权提交及推送。
- 每用户、每角色或多租户分别配置系统身份。
- 更多语言的独立系统名称。
- favicon 与页面图标分别配置、独立深浅色图标、图标编辑器或裁切工具。
- SVG、GIF、ICO 上传及远程图片 URL 输入。
- 邮件图标或邮件布局重新设计；本次邮件变更针对系统名称。
- 自动覆盖邮件发件人名称。
- 向其他已打开页面实时推送变更，或修改已经发送的历史邮件。
- 代码包名、仓库名、服务标识和构建产物名称的品牌重命名。
