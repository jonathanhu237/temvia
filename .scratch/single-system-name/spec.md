# 统一系统名称，移除独立英文名称

Status: resolved
Triage: ready-for-agent

## Problem Statement

Temvia 作为面向全球开发者的开源模板，支持中英文界面，是为了让不同地区的开发者和用户都能使用，而不是要求每次部署都维护多语言品牌名称。

现有“系统名称 + 可选英文系统名称”的配置隐含了主名称不是英文的前提。英文用户已经在 System name 中填写英文后，再看到 English system name，会困惑两个字段的区别。名称随语言切换还引入了没有明确需求支撑的配置、存储、接口与回退复杂度。

## Solution

一个部署只有一个系统名称，由管理员自由命名，不限定中文、英文或其他语言。中英文界面、浏览器标题和系统邮件统一引用这个名称；切换界面语言或邮件语言只改变相关文案，不改变系统名称。

彻底删除独立英文系统名称的能力，而不是隐藏字段、改名或增加高级翻译配置。项目尚未上线，不为旧英文名称提供兼容、迁移或保留机制。

## User Stories

1. As an 英文管理员, I want 只填写一个系统名称, so that 我不必猜测 System name 与 English system name 的区别。
2. As a 中文管理员, I want 使用中文为系统命名, so that 名称符合自己的部署需求。
3. As an 国际开发者, I want 系统名称不预设语言, so that 我能为自己的项目选择合适的品牌名称。
4. As an 管理员, I want 使用英文或混合语言名称, so that 无需额外配置即可表达品牌。
5. As an 用户, I want 切换界面语言时系统名称保持一致, so that 始终能够识别同一个系统。
6. As an 未登录用户, I want 登录页面使用统一系统名称, so that 在登录前即可识别应用。
7. As an 首次初始化用户, I want 初始化页面引用统一名称且不要求填写英文别名, so that 初始化流程不引入无关选择。
8. As an 受邀用户, I want 邀请邮件和接受邀请页面引用同一个系统名称, so that 清楚自己正在加入哪个系统。
9. As an 找回密码的用户, I want 密码找回与重置页面引用统一名称, so that 安全流程中的系统身份保持一致。
10. As an 已登录用户, I want 后台品牌区域与浏览器标题使用同一个名称, so that 不会因语言设置看到不同系统标识。
11. As an 管理员, I want 保存名称后刷新页面仍得到相同值, so that 配置能够可靠持久化。
12. As an 管理员, I want 中英文系统邮件都引用统一名称, so that 无需维护两份品牌配置。
13. As an 管理员, I want 邮件语言仍能独立于界面语言设置, so that 删除英文名称不会损失现有邮件国际化能力。
14. As an 只读管理员, I want 继续查看但不能修改系统身份配置, so that 原有权限边界不受影响。
15. As an 管理员, I want 名称必填和长度校验保持不变, so that 简化配置不会放松数据有效性要求。
16. As an 同时编辑设置的管理员, I want 保留并发修改冲突提示, so that 不会静默覆盖其他人的更新。
17. As an 管理员, I want 系统图标设置保持原样, so that 名称简化不会影响图标上传、保留或恢复默认。
18. As an 开发者, I want API 与前后端类型只表达一个系统名称, so that 新业务代码不必处理无用的语言分支。
19. As an 模板使用者, I want 新安装数据库只保存一个系统名称, so that 不携带已废弃的配置字段。
20. As an 模板维护者, I want 测试与当前文档反映单一名称模型, so that 后续开发不会重新引入双语名称假设。

## Implementation Decisions

- 领域定义为：系统名称是一个部署共享的显示名称，不指定语言，在页面、浏览器标题和系统邮件中保持一致。已在领域词汇表中确认，不再保留“英文系统名称”概念。
- 前端系统身份设置只保留“系统名称 / System name”字段；移除英文名称输入、说明、校验、草稿状态、提交内容与无用翻译键。不增加高级设置或名称翻译入口。
- 更新共享系统身份展示逻辑，直接使用统一系统名称；删除按界面语言选择名称及英文名称回退的分支。保留未配置时的默认系统名称行为，不混同默认值与语言回退。
- 初始化、登录、密码找回、密码重置、邀请接受、已登录后台和浏览器标题中所有系统名称引用遵循同一规则。不为本次改动新增初始化字段或步骤。
- 系统身份管理与公开读取 API 均移除 englishSystemName；管理写入契约不再包含它。不提供旧客户端兼容分支，额外字段按照现有通用请求解析策略处理，无需为该旧字段增加专用逻辑。
- 同步删除后端输入、视图、持久化投影、名称归一化及校验中的英文名称成员，并更新前端契约和相关测试替身。
- 系统邮件中的名称选择不再依赖邮件语言。邀请、密码重置、密码变更通知及其他已有品牌引用均使用统一名称；邮件文案语言、默认邮件语言、邀请语言和既有发送流程不变。
- 修改尚未发布的系统身份建表迁移和数据库访问逻辑，移除英文名称列及相关约束、读写参数。确保全新数据库可正常执行完整迁移，不增加历史数据转换或升级兼容迁移。
- 不读取旧英文名称来覆盖系统名称，不保留隐藏副本或弃用期。旧开发数据库如需使用新结构，应单独重建；本规格不授权自动删除正在使用的数据卷。
- 保留现有系统名称的归一化、必填、长度及安全校验语义。继续正确转义名称在页面和邮件中的输出。
- 保留系统身份读写权限、乐观并发控制、图标行为、操作历史记录及现有配置更新机制，不借此重构其他设置模块。
- 更新当前用户文档、开发说明、测试数据和生成模板中相关描述。历史讨论记录可以保留其历史语义，无需改写旧决策经过。

## Testing Decisions

- 用户已确认测试边界：以现有系统身份浏览器端到端测试为主，辅以现有 HTTP 契约测试、邮件测试及全新数据库验证，不新增测试架构。
- 好的测试应断言用户可观察的行为与公开契约，不断言内部帮助函数命名、调用次数或对象组织方式。优先改写已有双名称案例，避免各层重复相同断言。
- 浏览器测试：保存一个含中文、英文与特殊字符的名称，刷新后值保持一致；切换中英文，验证登录、账号相关公开页面、后台品牌区域和浏览器标题继续显示同一个名称。验证两种语言的系统设置均不存在英文名称输入，界面文案仍正常切换。
- 浏览器测试沿用已有系统身份端到端场景与隔离安装方式，更新保存与恢复测试配置的辅助逻辑；保留现有图标、并发冲突和操作历史覆盖。同步修正为执行本场景所必需的过时路由或定位方式，不扩展为全站测试重构。
- HTTP 测试：管理写入只提交统一名称即可成功，公开与管理响应不包含英文名称；保留默认名称、有效与无效名称、只读权限、未授权写入、版本冲突及图标相关的既有契约测试。
- 邮件测试：复用现有邮件派送与设置测试边界，验证中英文邮件使用同一个名称，同时各自的正文语言仍正确。覆盖已有邀请、密码重置、密码变更通知等名称引用，并保留特殊字符安全转义断言。
- 前端组件测试：按现有系统身份设置测试更新字段、草稿和提交断言；验证名称保存及原有只读、冲突行为，不为已删除字段保留兼容测试。
- 数据库验证：在一次性数据库执行全套迁移，通过实际数据库适配器保存和读取系统身份，确认单一名称可持久化，且不存在旧英文名称列依赖。不使用内存替身代替这一验证。
- 执行现有前后端检查、测试与构建，并执行受影响的生成器或模板打包检查，确保分发产物与源码契约一致。端到端验证应实际启用对应测试开关，跳过的测试不能计为通过。

## Out of Scope

- 多语言名称字典、按语言配置品牌、高级翻译设置及自动翻译。
- 根据浏览器语言、邮件语言或操作者语言自动选择或改写系统名称。
- 旧英文名称数据保留、迁移、自动覆盖、旧 API 客户端兼容及已上线部署升级方案。
- 修改界面支持语言、默认邮件语言、邀请语言或邮件派送语义。
- 更改系统图标、权限模型、导航结构、设置页面整体设计或其他账号功能。
- 自动清空现有本地预览环境或共享数据库。
