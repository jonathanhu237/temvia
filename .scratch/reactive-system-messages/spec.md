# 管理端系统提示随语言切换更新

Status: resolved
Labels: ready-for-agent

## Problem Statement

管理端用户在某种语言下触发提示后切换语言，页面标题、按钮和标签已经更新，部分已有提示却仍停留在原语言。例如中文登录失败后切换英文，登录表单仍显示中文的“邮箱或密码不正确。”，造成同一页面混用语言，用户需要重新操作才能获得当前语言的反馈。

这一问题并非只存在于登录：初始化、密码重置、接受邀请、退出失败及邀请用户校验也有相同模式。用户需要整个管理端的现有系统提示保持语言一致，同时保留已经填写的内容和当前操作状态。

## Solution

管理端切换简体中文或英文时，所有仍显示的系统提示立即使用当前语言展示，包括表单级错误、字段校验、成功提示和页面反馈。已经出现的提示不需要重新触发，反复切换语言也始终保持一致。

语言切换只更新展示，不清空输入、选项或错误，不重置表单状态，也不主动触发提交或重新校验。对于已经发出但尚未完成的请求，结果到达后按届时选中的语言展示，且不因为切换语言而取消、重发或重复执行操作。

系统提示是应用提供的界面反馈。姓名、邮箱、角色名称等用户数据保持原值。此功能覆盖现有提示，不增加通知类型或新的业务流程。

## User Stories

1. 作为登录用户，我希望登录失败后切换语言时已有错误立即更新，以便使用当前语言理解登录失败的原因。
2. 作为登录用户，我希望切换语言后已填写的邮箱和密码保持原值，以便无需再次输入即可修改或重试。
3. 作为首次初始化系统的管理员，我希望初始化失败的表单级提示随语言切换更新，以便继续完成初始化。
4. 作为首次初始化系统的管理员，我希望姓名、邮箱、密码等字段的服务端校验提示随语言切换更新，以便准确定位需要修正的内容。
5. 作为申请重置密码的用户，我希望已有请求失败提示随语言切换更新，以便理解发送重置链接时遇到的问题。
6. 作为申请重置密码的用户，我希望发送频率受限时仍看到当前语言的密码重置专用提示，以便理解相应的重试限制。
7. 作为申请重置密码的用户，我希望发送成功后仍显示的成功提示随语言切换更新，以便确认请求已被处理。
8. 作为设置新密码的用户，我希望重置失败时的表单级及字段级提示随语言切换更新，以便修改新密码或按提示继续操作。
9. 作为设置新密码的用户，我希望重置成功页面随语言切换更新，以便理解后续登录操作。
10. 作为受邀用户，我希望接受邀请失败时的已有错误随语言切换更新，以便继续完成账户启用。
11. 作为受邀用户，我希望密码校验及邀请接受成功后的提示使用当前语言，以便完整理解邀请流程中的反馈。
12. 作为尝试退出登录的用户，我希望退出失败提示及其相关操作文案保持语言一致，以便知道如何重试。
13. 作为邀请用户的管理员，我希望邀请表单已有的本地必填提示随语言切换更新，以便继续补充必需信息。
14. 作为邀请用户的管理员，我希望切换语言后已填写的姓名、邮箱及已选角色保持不变，以便不丢失邀请草稿。
15. 作为管理用户和角色的管理员，我希望接口失败、权限不足及冲突提示始终使用当前语言，以便理解现有的重试或重新加载操作。
16. 作为编辑角色的管理员，我希望已有的本地校验提示随语言切换更新，以便继续编辑角色。
17. 作为填写任意管理端表单的用户，我希望已有客户端校验提示和服务端校验提示都能更新，以便不必区分错误来自哪里。
18. 作为填写表单的用户，我希望切换语言后错误仍关联原来的字段，以便继续修正同一个问题。
19. 作为填写表单的用户，我希望切换语言时保留已编辑、已访问字段的状态及密码显示状态，以便继续当前操作。
20. 作为切换语言的用户，我希望现有提示保留相同含义和处理方式，以便语言变化不会被误认为问题已经解决。
21. 作为等待请求结果的用户，我希望切换语言后到达的反馈使用当时选中的语言，以便不再看到提交时语言的旧提示。
22. 作为等待请求结果的用户，我希望切换语言不会重复发送请求，以便避免重复登录、发送邮件、接受邀请或执行管理操作。
23. 作为反复切换语言的用户，我希望提示在中英文之间往返切换都能正确更新，以便不会出现第二次切换失效或旧文案残留。
24. 作为遇到未知错误或网络故障的用户，我希望看到当前语言的可理解提示，以便知道操作是否失败及如何继续。
25. 作为使用管理端的用户，我希望错误反馈继续隐藏内部诊断信息和消息标识，以便界面只显示面向用户的文案。
26. 作为使用辅助技术的用户，我希望翻译后的提示继续与原字段关联并保留已有提示语义，以便仍能理解错误位置和反馈内容。
27. 作为查看管理数据的管理员，我希望切换语言只翻译系统反馈而不改写姓名、邮箱或自定义角色名称，以便准确识别原始数据。

## Implementation Decisions

- **覆盖范围**：统一处理整个管理端的现有系统提示。已核实需要修复的七处业务界面为登录表单、管理员初始化表单、密码重置请求表单、密码重置表单、邀请接受表单、登录后的页面框架中的退出失败提示，以及用户管理中的邀请表单本地校验。
- **状态与译文分离**：需要保留的提示保存与语言无关的错误信息、消息标识及必要参数，在渲染时使用当前语言生成文案。具体内部类型由实现选择；不强制新增通用消息框架。
- **表单级错误**：认证、恢复及邀请表单复用现有问题分类与本地化映射，避免在异步回调中将当时的译文固化为状态。
- **字段级错误**：共享字段错误展示需统一支持客户端校验和服务端校验的语言无关表示，保留原字段关联、错误类型和既有聚焦行为；不再直接展示服务端字段状态中保存的旧译文。
- **专用文案和回退**：沿用现有问题类型、错误码、字段码和翻译资源。保留密码重置限流专用文案及未知错误、网络错误、协议错误的现有回退规则；不直接展示服务端诊断文本。
- **本地校验与退出反馈**：邀请表单的本地校验保存校验状态或消息标识；退出失败保存可重新翻译的错误信息。文案更新遵循同一规则。
- **已有正确路径**：客户端字段错误、用户与角色管理的页面错误、角色编辑本地校验，以及密码恢复和邀请接受成功页面已经存在渲染时翻译的实现。将其纳入行为覆盖和回归验证，避免不必要的重写。
- **状态保留**：语言切换不重挂载表单，不重置输入、角色选择、密码显示、错误、已编辑或已访问状态，也不额外移动焦点到错误字段。语言菜单自身的正常焦点交互保持原行为。
- **校验时机**：不因语言变化显式重新执行校验。字段正常输入或失焦原本会触发的校验仍按既有规则执行，不将正常表单交互误当作语言切换副作用。
- **请求时序**：正在进行的操作保持既有生命周期。语言切换不修改已发送请求的内容、不取消或重发操作；结果展示使用当前语言。新的用户操作仍沿用原有提交及语言参数规则。
- **业务行为**：错误的清除时机、重试、导航、会话处理、邀请和密码重置权限校验保持既有语义；仅修复消息的语言响应性。
- **系统边界**：不修改数据库结构、后端 API 契约、权限规则或邮件投递流程；不增加语言或新的翻译来源。
- **测试可用性**：优先复用真实页面、现有可访问控件与 API 边界，不为测试新增生产环境的表单状态暴露接口。

## Testing Decisions

- **测试质量标准**：验证用户可观察到的行为：现有提示是否换成目标语言、旧译文是否消失、字段值与选择是否保留、后续交互是否延续，以及请求是否被额外触发。不要通过断言内部状态结构、翻译函数调用次数、组件渲染次数或大段快照来替代行为验证。
- **主要测试边界**：复用现有 Playwright 浏览器测试，从实际页面及语言菜单完成“产生提示 → 切换语言 → 观察结果”的完整流程。这是现有最高层的用户行为边界，至少覆盖原始登录复现和登录后页面的语言切换。
- **确定性补充边界**：服务端字段错误、退出失败和请求延迟等难以在真实服务中稳定触发的情况，复用现有表单及页面集成测试，在已有 API 客户端边界提供受控响应。继续使用真实翻译资源和用户交互；不拆出新的底层测试体系。
- **优先复用的先例**：现有认证表单测试已使用 Testing Library、user-event、独立查询客户端和模拟 API 检查中英文校验、错误展示、字段关联与聚焦。用户与角色管理测试已有权限、冲突、本地校验和表单选择的行为测试。浏览器认证流程已有登录错误、语言菜单、会话、退出及可访问性检查。
- **既有映射测试**：保留已有共享问题映射及专用限流文案测试。如果修改其对外契约，按公开行为更新受影响用例；不将本次主要回归验证限制在映射函数。
- **表单状态验证**：通过输入值、选中项、密码显示、错误关联、提交按钮状态以及后续正常编辑或失焦的表现验证状态延续，避免直接读取表单库的内部状态。
- **时序验证**：控制请求完成时机，先提交，再切换语言，最后返回失败或成功结果；断言结果使用当前语言。统计相应业务操作的请求次数，不把初始化查询或正常交互产生的请求混为重复提交。
- **切换方向**：至少有一个完整场景覆盖“中文 → 英文 → 中文”；对受影响业务界面验证已有提示确实能在切换后更新。使用隔离的语言及查询状态，避免用例之间互相影响。
- **测试范围控制**：七处已发现的缺陷路径都需要行为覆盖，已有正确路径按消息类别补充代表性回归验证。避免把同一错误映射与所有页面、所有语言做无意义的笛卡尔积组合。

验收矩阵：

| 场景 | 必须观察到的结果 |
| --- | --- |
| 中文登录失败后切为英文，再切回中文 | 原错误立即对应切换，邮箱和密码保持原值，登录请求不增加 |
| 初始化、密码重置请求、密码重置、邀请接受发生表单级错误后切换 | 提示使用当前语言，原输入及操作状态保留 |
| 上述五个表单出现服务端字段错误后切换 | 错误仍对应原字段，译文更新，错误关联语义不丢失 |
| 已有客户端校验提示后切换 | 译文更新；没有因语言变化额外产生、清除或替换校验结果 |
| 邀请用户必填校验后切换 | 本地提示更新，已填写数据和角色选择保持 |
| 退出失败后切换 | 错误标题、正文及操作文案语言一致，没有额外退出请求 |
| 用户或角色管理页面已有接口错误后切换 | 现有权限、冲突及失败提示继续正确更新，恢复操作语义保持 |
| 角色编辑已有本地校验后切换 | 校验文案更新，编辑内容保持 |
| 密码重置请求、密码重置或邀请接受成功后切换 | 已显示的成功提示更新，不重复执行成功操作 |
| 请求进行中切换后返回失败或成功 | 使用完成时的当前语言，原业务请求仅执行一次 |
| 未知错误、网络错误、协议错误及未知字段码 | 保留当前语言的原有回退提示，不显示内部诊断或消息标识 |
| 密码重置频率受限后切换 | 保留密码重置专用含义，正确切换译文 |
| 反复切换并继续修改或重试 | 输入、选择及既有表单交互语义延续，提示不会恢复旧语言 |
| 使用辅助技术关联字段错误 | 已有可访问名称、字段错误关联和提示语义保持有效 |

实现后的验证按项目工作流进行：本地修改已完成并单向同步至 Centaurus，管理端测试已在本地和 Centaurus 通过；完整 Playwright 流程仍需配置 `E2E_SETUP_URL` 的栈后运行。

## Out of Scope

- 新增语言、重写现有翻译内容，或改变现有文案表达的业务含义。
- 翻译、修改或持久化用户输入及业务数据。
- 改变客户端或服务端校验规则、错误分类、错误清除策略、重试策略、权限规则或业务流程。
- 改变已发送邮件、邮件模板、后端日志或历史记录的语言；改变已在途请求中的语言参数。
- 新增消息中心、通知历史、toast 使用场景，或追溯更新已经消失的提示。当前代码仅挂载 Toaster，未发现实际 toast 调用。
- 将浏览器原生确认框替换为自定义弹窗；此类模态窗口打开期间无法通过页面控件切换语言，其后续打开仍按现有方式使用当前语言。
- 为跨刷新、跨页面、跨设备恢复表单内容或错误状态新增持久化能力。
- 数据库迁移、API 契约调整或新的领域架构。
- 大范围视觉调整、表单结构重构、国际化基础设施替换或新增测试框架。
